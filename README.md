# AVHub

Windows 本地视频库。运行时离线使用，源视频只读，索引、播放记录和缩略图保存到应用目录的 `data/`。

## Git 版本管理

仓库保留源码、测试、脚本、文档、应用图标、`package-lock.json` 和 FFmpeg 许可/构建说明。依赖、`data/` 与 `AVHub-data/`、用户截图、数据库、日志、测试报告、构建缓存、网页/Electron 编译结果、打包 EXE、FFmpeg 可执行文件及私密环境配置均排除；忽略规则不会删除本地文件。

克隆后先安装 Python/npm 依赖，并重新构建网页和桌面代码；`app/build-info.json` 会在 `npm run build` 时自动生成。桌面验收和 Windows 打包需要另行准备 `bin/ffmpeg.exe` 与 `bin/ffprobe.exe`。原视频 `.ts` 不应复制到源码目录：`.ts` 也是 TypeScript 后缀，不能全局忽略；其他常见视频后缀已排除。

## 快速开始（开发）

1. 安装 Python 3.11+ 与 FFmpeg（或将 `ffmpeg.exe`、`ffprobe.exe` 放到 `bin/`）。
2. `python -m pip install -r requirements.txt`
3. `npm install && npm run build`
4. 双击 `启动AVHub.bat`，或运行 `python run.py`。

首次打开后，在“媒体库设置”中输入如 `D:\\Videos` 的本地目录，点击刷新媒体库。所有索引、缩略图、播放记录存储于 `data/`，源视频绝不会被移动、删除或改写。

## Electron Windows 便携包

桌面版由 Electron 窗口承载现有 React 页面，Electron 启动并关闭打包后的 FastAPI 子进程；扫描、SQLite、播放和 FFmpeg 逻辑继续复用 Python 服务。准备 Python 3.11+、Node.js/npm，并将 Windows 版 `ffmpeg.exe` 和 `ffprobe.exe` 放入项目 `bin/` 目录，然后在 PowerShell 7（`pwsh`）执行：

```powershell
pwsh -NoProfile -File .\scripts\build-windows.ps1
```

生成 `dist/electron/AVHub-portable-0.2.0-x64.exe`。运行时无需单独安装 Python、Node.js 或 FFmpeg。便携单文件程序会把用户数据存到 EXE 同目录的 `AVHub-data/`；如果该目录不可写，则使用 `%APPDATA%/avhub/data`。可通过 `AVHUB_DATA_DIR` 指定数据库和缓存位置。当前打包使用 FFmpeg 9.0.2 essentials GPLv3 构建，FFmpeg 许可证及构建信息随媒体服务一同打包；重新分发时须遵循对应许可证。便携包首次构建需要下载 Electron/Chromium 和构建依赖；生成后的应用可离线运行。

开发桌面壳可运行 `npm run electron:dev`；该命令需本机 Python 依赖已安装，并使用已构建的 `app/static`。

当前迭代只更新源码和开发页面，不重新生成便携包。请用 `npm run electron:dev` 或 `python run.py` 验证新逻辑；已有的 `dist/electron/` EXE 仍使用它打包时的后端和页面，重启旧 EXE 不会加载本次更新。

“媒体库设置”支持下载 SQLite 备份和恢复备份。备份仅包含 AVHub 索引及用户数据，不包含视频本身；缺少的缩略图会在重新扫描时生成。恢复前需停止扫描并关闭播放中的视频；恢复操作会在数据目录的 `backups/` 中保留当前数据库副本。若已登记的目录离线，重新接入磁盘后点“重新定位”，选择它的新位置，再刷新媒体库即可保留对应影片的收藏、进度和手工信息。

## 大型媒体库版（0.2）

- 分类、目录、搜索和视图统一管理；切换目录无需刷新整页，返回播放器前的媒体库时保留筛选及滚动位置。
- 收藏采用明确的“收藏/取消收藏”请求，卡片和播放页同步更新，提交过程中禁止重复操作。
- 有历史进度的视频先显示续播选择，选择前不自动播放、不覆盖原进度；暂停、拖动完成、返回、切后台及关闭页面时补存进度，播放过程中每 8 秒保存一次。
- 迟到的旧进度请求不会覆盖新记录。返回时保存失败会提示重试，也可自行选择直接返回。
- 自动画质先尝试原片直放，MKV/TS 不会仅因后缀被强制转码。原片失败后不重复请求同一地址；H.264 视频优先复制视频编码重封装，只有编码不兼容或重封装播放失败时才转码。成功直放的视频重播仍走直放。手动画质和音轨选择优先于原片尝试。
- 原片提供准确的媒体类型及标准 HTTP Range/HEAD 响应，包括分段、尾部读取和 If-Range 校验；每次读取最多 1MB，不整片加载到服务内存。TS/M2TS 使用 `video/mp2t`，不再误标为 MP4。
- 播放器下方提供完整视频进度条。已发布的 HLS 分段优先复用同一任务，尚未生成的目标或当前流起点之前的位置才重新准备播放流。浏览器前向缓冲目标 30 秒、上限 90 秒，后向保留 30 秒，避免长视频持续积累已解码缓冲；原片直放不使用这些 HLS 限制。
- 播放器的折叠“播放信息”显示实际播放模式、选择原因、解码分辨率、起播到首帧及最近跳播到画面的耗时。支持的浏览器使用视频帧呈现回调测量，不只统计进度条移动；不支持时使用媒体就绪事件估算。数据包括本机处理、读取和解码，不能单独作为硬盘速度或画质无损的证明。
- 播放结束、返回和页面关闭后停止对应转码并清理该任务的缓存；浏览器异常退出时，120 秒无访问的任务会被回收。
- 播放缓存按进度滚动，单任务节流目标为 1.5GB，预留在途分片与编码缓冲空间；不是对单个超大 GOP 的严格磁盘配额。最多同时两个任务。保留前向约 90 秒、后向最多 60 秒，容量紧张时后向收缩至约 10 秒；回看已回收区间会重新取流，不降低画质以适应缓存。自动兼容转码尽量保留源分辨率，H.264 使用 CRF 18、medium 预设；手动选择 1080p/720p/480p 时按档位缩放。转码仍是有损编码，8-bit 4:2:0 输出无法完全保留 10-bit/HDR 源片的全部信息。转换失败可重试，磁盘满及持续大量 FFmpeg 错误单独提示。
- 媒体列表使用服务端分页与真实总数，不再只取前 300 条；支持每页 24/48/96 条、跳页，以及最近观看、最近添加、名称和时长排序。分类、目录、搜索、排序、页码保存在地址栏，可复制或刷新后恢复。
- 高级筛选可组合格式、观看状态与时长范围；选择条件会进入地址栏，刷新或分享当前页面链接可恢复筛选。
- “观看历史”单独列出已播放视频，按最近观看排序并展示最近播放时间和观看进度；可逐条清除历史，源视频和媒体索引不受影响。
- 封面缩略图采用浏览器懒加载；播放器与 HLS.js 按需拆分，浏览媒体库时首屏资源更小。播放器支持滚轮按指针缩放、放大后拖动画面、一键还原、90°旋转、空格/K 播放暂停、方向键 5 秒跳转、方向键调音量、M 静音和 F 全屏，并显示缓冲状态；倍速偏好保存在本机，切换影片后沿用。播放控件在明亮画面上使用局部暗色底和阴影增强可读性，控制栏本身保持透明。后台索引进程在 Windows 降低优先级以尽量让位于播放。
- 播放页提供自动/原画、1080p、720p、480p 画质选择；多音轨视频可切换音轨，选择后从当前进度以 HLS 重开。统一控制栏提供 ±10 秒、倍速、音量、全屏和浏览器支持时的画中画。播放列表支持新建、重命名、删除、添加/移除视频、调整顺序、顺序播放及前后切换；剧集结束后可倒计时连播下一集。播放器可选内嵌文本字幕（由 FFmpeg 转为 WebVTT）、自动发现同目录 SRT/VTT 字幕，或加载本地字幕；字幕支持 0.1 秒步进延迟、字号/颜色/底色调整与本机偏好记忆，以及 UTF-8、UTF-16、GB18030/GBK 字符编码。
- 扫描在后台执行，支持查看发现与处理进度、当前文件、逐项错误，以及取消任务；取消会中止当前 FFprobe/FFmpeg 子进程，不等待该文件处理到超时。
- 设置页可单独刷新某个目录；扫描期间禁止增加/移除目录，并提示磁盘离线。扫描只在完整读取的目录上标记消失文件，取消、离线盘或部分访问错误不会清空现有索引。
- 同名/重叠目录扫描会将视频归属到最深层的已登记目录；文件内容变化时刷新技术信息，同时保留用户编辑的标题、标签、评分和观看记录。

更新后请关闭旧启动窗口，重新双击 `启动AVHub.bat`，再强制刷新浏览器。只刷新网页不会更新 Python 服务。

### 本轮迭代：字幕、大片单、预览与色彩

本轮按用户要求暂缓真实文件跳播基准，不改跳播策略、不接入 MPV、不生成新的便携 EXE。

- 外挂 ASS/SSA：自动发现影片同目录的匹配字幕，也可通过“加载字幕”手动选择。本机 FFmpeg 只把对白转为 WebVTT，支持 UTF-8、UTF-16 和 GB18030/GBK；保留字幕延迟与外观设置。高级定位、字体、动画、卡拉 OK 特效不保留，不烧录、不转码视频。转换限制 4MB、30 秒、最多两个任务，返回后回收任务临时文件；关闭字幕、切换字幕或离开播放器后不接受迟到结果。
- 大播放列表：管理弹窗与播放器队列每页 40 条，搜索、定位和相邻条目由 SQLite 查询。移动只提交当前条目与方向，支持跨页移动；修改使用版本号拒绝过期顺序。离线条目仍显示、可移除，但从头播放、上一条/下一条与结束连播跳过离线项。旧的完整列表 API 为兼容保留，当前界面不使用它。
- 悬停预览：媒体库设置中的“封面悬停预览”默认关闭。开启后鼠标停留 0.65 秒才静音预览原片，循环约 6 秒片段，每次最多一个；移开、切页、离开媒体库或切后台即停止。浏览器不兼容时保留封面，绝不为预览请求播放/转码任务。开启会增加原片读取及解码负载，不建议在大库或慢网络盘上常开。
- 色彩策略：扫描保存像素格式、位深、传递曲线、色域与范围；旧库只在需要兼容转码时补测，不为升级全库重新分析。直放与复制视频编码的重封装均不改色彩。PQ/HLG 兼容转码使用浮点线性化、色域转换、Hable 色调映射和抖动，输出明确标记的 SDR BT.709 / 8-bit。10-bit SDR 降至 8-bit 时抖动并保留已知色彩标记。处理依据 [FFmpeg zscale/tonemap 官方说明](https://github.com/FFmpeg/FFmpeg/blob/master/doc/filters.texi)。HDR/10-bit 转码仍有损，不能等同原画；自动档尽量保留原尺寸，手动画质仍按档位缩放。
- 播放信息显示源色彩、实际策略及损失提示。HDR 缺少色域/矩阵/范围时明确提示兼容默认值；动态 HDR 只处理兼容基层、不应用动态元数据。不支持的 Dolby Vision 基层拒绝兼容转码。缺少 zscale/tonemap 或映射失败会报错，不偷偷输出未经映射的 HDR。原片 HDR 显示仍取决于系统、显卡、浏览器与显示器。

回归覆盖 10,000 条片单的分页、跨页移动、离线跳过与冲突保护；真实 ASS/SSA 转换、编码与延迟、迟到请求取消；预览单实例及停止读取；合成 PQ、HLG、10-bit SDR 的实际 HLS 输出标记、位深与源文件哈希不变。短 3840×2160 PQ 样本验证自动转码输出仍为 4K，浏览器验证实际 HDR→SDR 播放。以上不代表所有真实片源色彩已得到逐片主观校准，也不代表长时间 4K 转码性能或所有 Dolby Vision 均已验证。

### 本轮迭代：便携偏好、播放页恢复与操作菜单

- 音量/静音、倍速、字幕外观、预览开关、队列展开状态、播放模式及自动连播开关存入 SQLite；每个视频的字幕选择与延迟按需读取，不一次拉取全库设置。旧浏览器偏好只补入数据库尚未保存的项目，数据库为准。设置写入合并并拒绝迟到的旧写入，失败可重试；媒体库备份包含这些偏好，恢复后重新载入界面。跨 Electron 随机端口重启也能保留。
- 播放页地址使用 `video=<索引ID>`，片单使用 `playlist=<索引ID>`，与原有 `watch=watched/unwatched` 筛选分开。刷新仍停留在当前视频，已有进度先询问续播；浏览器返回/前进保留媒体库筛选与位置，切换条目不堆积历史。返回前先保存进度，失败保留当前播放页；失效视频和片单上下文会提示并安全回退。重新启动桌面应用保留设置与观看进度，但不自动恢复上次打开的视频页面。
- 卡片和播放页新增紧凑“更多操作”菜单：手动标记已看/未看、恢复自动判断、复制路径、在资源管理器定位、用系统默认播放器打开。手动标记不伪造播放进度、不改变历史日期，自动进度保存不会覆盖它；清除观看历史仍保留手工已看选择。定位/外部播放只接受已索引的视频 ID，原文件始终只读；外部播放需确认，无法回传外部播放器的进度、音轨和字幕。
- 折叠待播区提供顺序、随机、单条循环及自动连播开关。随机从完整可播放片单或当前实际目录选择，不限当前页、排除当前及已标离线项；它不是无重复洗牌，普通顺序目录电影仍默认结束即停。关闭连播后结束即停，仍可手动播放下一条或重新播放。新增 J/L（±10 秒）、N（下一条）、P（画中画）、C（截图）的快捷入口；帮助折叠显示，菜单/输入框内不触发播放器快捷键。
- Electron 关闭窗口或退出前等待设置与当前进度提交，再停止本机服务；失败可重试、仍然退出或取消退出。强制结束进程、断电和浏览器强制关闭不保证最后一瞬间的进度能够提交。

本轮不改变原片/重封装/转码及跳播策略，不接入 MPV，不生成新 EXE。测试使用隔离数据库与合成视频，不打开日常视频或实际启动外部播放器。

### 窗口播放：纯净播放与置顶

- 播放控制区“纯净播放”图标（W）：桌面窗口自动适配解码后视频的实际显示宽高比，支持横屏、竖屏、4:3、超宽视频，切换视频或旋转 90° 后同步调整。尺寸以当前窗口面积为参考，居中调整并限制在所在显示器的可用工作区；原分辨率不变，不拉伸、不裁切、不重启解码。视频自身编码中的黑边不会被删除。
- 纯净播放时隐藏页面顶栏、队列、媒体信息及桌面标题栏；拖动窗口边缘保持视频比例，标题栏“最大化”按视频比例放大至工作区内最大尺寸，再次点击恢复小窗。退出纯净播放恢复进入前的窗口位置、大小及最大化状态。系统视频全屏独立保留，屏幕与视频比例不同时仍会有黑边。
- 纯净播放右上角使用独立悬浮圆形窗口按钮，与底部播放控件保持相同半透明底色、细线图标及阴影，无矩形底板、渐变或模糊滤镜；距窗口边缘保留小间距。置顶保持主题色状态，关闭仅悬停时显示红色，支持键盘焦点和减少动态效果；普通模式仍使用标准紧凑标题栏。
- 桌面端页面在标题栏下方独立滚动：右侧滚动条从关闭按钮下方开始，标题栏保持完整宽度，不被滚动条挤占。媒体库/播放页顶栏在内容区内吸顶，打开视频及返回时仍保存/恢复原滚动位置，翻页回到内容顶部；纯净播放隐藏页面滚动条。浏览器版保持原生页面滚动。
- 已隐藏的播放控制栏不会因键盘播放/暂停、跳播、音量、静音、旋转或切换全屏而弹出；键盘 N 切换下一条也延续隐藏状态。移动鼠标、点击画面或 Tab 主动聚焦控件可重新显示；设置菜单展开时仍保持可见。普通播放、纯净播放及视频全屏使用同一规则。
- 桌面端“窗口置顶”图标位于标题栏最小化按钮的左侧，可独立开关；使用统一线条的斜图钉，开启后填充并以主题色高亮，播放控制栏不再重复显示。纯净播放的小窗最小尺寸随比例调整（16:9 约 480×270，9:16 约 270×480），顶部透明区域可拖动/双击窗口，保留系统边缘缩放和最小化、最大化、关闭按钮；播放时控件与鼠标快速隐藏，移动鼠标恢复，设置菜单展开时不隐藏。Esc 或 W 退出纯净播放；视频全屏仍独立使用 F / 控制区最右侧图标。
- 切换上一条/下一条保持纯净播放和置顶；保存成功返回媒体库后恢复普通布局并取消置顶，保存失败仍停留当前窗口。置顶是本次运行状态，不在下一次启动时自动开启。自绘标题栏关闭按钮仍经过退出前保存流程。

### 预览图缺失修复

媒体库各分类的封面墙与列表共用预览图组件，加载失败显示占位提示，不再直接留白；图片重新生成后以版本化地址自动重试。增量扫描会检查缓存是否缺失、为空或截断，补图不重新探测未变化视频的技术信息。短视频截图不再强制跳到第 1 秒，必要时退回首帧；生成过程使用临时 JPEG，完成后再替换，避免页面读到半张图片。所有写入只发生在缓存及索引中，原视频保持只读。

更新源码并重启后点击“刷新媒体库”即可补齐旧缓存；离线、损坏或无法解码的文件可能仍无预览图，会保留占位提示。本轮不打包、不自动扫描日常视频目录。

```powershell
npm run benchmark:seek -- --source "D:\Videos\sample.mkv" --reference "D:\AI\codex\local-video-player"

# 强制 AVHub 走重封装，单独验证后备路径
npm run benchmark:seek -- --source "D:\Videos\sample.ts" --mode remux
```

基准使用同一 Edge、同一文件、两套临时数据库，并在计时前缓存封面；不启动对照项目的日常数据库，也不改写源视频或对照项目。输出到 `build/seek-benchmark/report-*.json`，包含播放模式、首帧时间、12 次跳播的呈现耗时、中位数/P95、解码分辨率和掉帧计数。参考应用由脚本在元数据就绪后触发播放，避免把手动点击等待混入计时。源码有不同接口或播放失败时报告不完整，不当作成功样本。

不会清理操作系统文件缓存；两应用按顺序运行，因此报告不是冷盘对比，也不等同于 Electron 的硬件解码表现。先用自动模式确认实际播放路径，再分别比较原片直放和重封装；合成样本不能证明实际高码率、长 GOP、10-bit/HDR 或网络盘视频的速度。

### 回归测试

```powershell
npm run build
npm run build:electron
npm run test:electron
npm run test:electron:preferences
npm run test:electron:shutdown
npm run test:electron:logs
npm run test:electron:window
npm run test:backend

```

`npm run test:electron` 会使用 `build/` 下独立临时目录启动桌面壳，检查 API、页面加载和退出清理；它不是打包命令，不会读取日常媒体库或生成便携 EXE。

`npm run test:electron:preferences` 连续启动隔离的隐藏 Electron 窗口，保证前后端口不同，验证 SQLite 设置保留、退出前保存进度和保存失败后的取消退出；只生成临时纯色视频。

`npm run test:electron:shutdown` 验证退出限时策略和仅终止自有进程树，并用合成剧集验证原片连接未结束、MKV 转码纯净播放、起播请求未完成时关闭窗口，以及重启后进度保留。使用隔离测试目录，不读取日常媒体库、不生成 EXE。

`npm run test:electron:logs` 验证单个日志最大 4MB、仅保留两份历史、超大消息及目录不可写的处理。长片专项可运行 `python -m unittest discover -s tests -p test_long_term.py` 和 `npm run test:ui -- tests/ui/long-term.spec.ts`；先执行 `npm run build`，确保源码、页面和诊断构建标识一致。

浏览器测试使用本机 Edge，在 `127.0.0.1:8877` 启动临时服务，生成纯色测试视频和独立数据库；不会读取或改动日常媒体库。需要本机 FFmpeg、Python 依赖和 npm 开发依赖。

新增测试覆盖原片 Range 字节正确性及源文件只读、MKV 直放的播放中/暂停跳播和重播、原片失败只回退一次，以及 TS 跳到当前流起点之前后恢复画面。合成样本通过不代表所有大码率、长 GOP、10-bit/HDR 或损坏索引视频都已达到同等速度；实际文件可展开“播放信息”核对路径与耗时。

### AVHub 应用图标

桌面窗口使用 `electron/assets/avhub.png`，未来 Windows 打包使用同目录的
`avhub.ico`，替换默认 Electron 图标。图标采用现有深蓝/珊瑚色配色，透明圆角；
ICO 内含 16、24、32、48、64、128、256px，兼顾任务栏、Alt+Tab 及资源管理器。
生成原图和提示词保存在 `electron/assets/`；尺寸导出脚本为
`scripts/prepare-app-icon.py`（需 Pillow），不参与用户日常启动。

源码版重启 `npm run electron:dev` 后应用新图标；已打包的旧 EXE 不会被改写，
最终打包时才更新其文件图标。`npm run test:electron:icon` 在隔离数据目录中
验证多尺寸 ICO、原生 PNG 读取、开发/打包资源路径和桌面启动，不生成新 EXE。

## 仍待后续迭代

- 扫描目前由用户手动开始；桌面端退出时会安全暂停扫描，下次启动可从头继续（扫描本身是增量的，已处理文件不会重复分析）。崩溃后遗留的扫描也会提示继续。媒体库设置已支持离线目录重新定位和数据库备份恢复。
- 字幕支持外挂 VTT/SRT/ASS/SSA 和可转换的内嵌文本轨（如 SRT、ASS/SSA 文本、MOV_TEXT）；ASS/SSA 转 WebVTT 时不保留高级样式。PGS/VobSub 等图像字幕轨尚不支持。字幕抽取是本机临时转换，不会修改原视频。
- 播放页现可编辑显示标题、电影/剧集类型、季集号、1–5 星评分和标签；这些只写入 SQLite 并在扫描中保留。
- Windows x64 便携包已构建；包内媒体服务的本机健康检查通过。仍需在干净 Windows 机器上验证，并测试不同盘符及只读目录下的数据回退行为。
- 本版只回收本版创建的转码任务缓存；旧版遗留目录不会自动删除。
- 真实 MKV/TS/4K 文件跳播基准按用户要求暂缓，需要时再处理。本轮已接入外挂 ASS/SSA 文本转换、可关闭的原片悬停预览、大播放列表服务端分页及 HDR/10-bit 兼容色彩转换。后续可评估完整 ASS 样式渲染、图像字幕，以及真实 HDR/Dolby Vision 片源和不同显示设备的色彩验证；不能把保留分辨率等同于保留全部画质。最终稳定后再打包。
