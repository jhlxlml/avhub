## 启动与双格式交付

- 手动更新识别并分别展示已上传的文件夹 ZIP、单文件 EXE；ZIP 单独存在也可识别。只接受本仓库、对应版本的精确文件名与下载 URL。点击才打开，原生 IPC 仅接受格式枚举，不接收任意 URL。
- 正式运行也记录 backend-start、backend-ready、window-created、renderer-loaded、library-ready 的单调时钟偏移；同一启动的 ready 消息去重。外层自解包由验收脚本在 spawn 前开始测量，不能用 Electron 内部计时冒充完整启动。
- 本地实际生成并验收 EXE 与从最终 ZIP 解压的 AVHub.exe。发现依赖内 `.agents` 被 collect-all 收集的问题，已在两个格式共用的 backend 资源过滤中排除隐藏元数据，并保留 ZIP 的拒绝校验。
- 两种格式通过冻结后端/FFmpeg、同级数据目录、实际迁移、偏好保留、旧库保留和迁移后再次启动。更新 UI 在这项验收中使用模拟 GitHub 响应，明确不算真实联网检查。

## 播放器状态整理

- 控制栏与光标状态及其计时、悬停、按压、焦点、菜单保护提取到 `usePlaybackChrome.ts`；窗口状态仍由独立 windowMode 模块与 Electron 管理。
- 不移动播放地址、解码、跳播、转码权限或进度保存逻辑。原画优先策略不变。
- 22 项播放器/手动更新界面回归通过；真实 Electron 验证光标连续移动、停动、悬停、W/Esc、置顶、冲突 IPC，以及同一 video 节点、地址、时间与暂停状态。固定域名下载 IPC 使用 shell 模拟，未打开外部页面。

## 大库浏览与 UI

- 目录树首次启动默认收起；打开后本会话记住展开、分页和滚动。未打开不创建树 DOM；打开过再隐藏时保留有界 DOM，暂停目录请求。
- 每层页码记忆和目录缓存各有 128 项上限；最多 32 个手动展开分支，仍按每层分页渲染。隐藏时立即更新缓存 revision，显示期间合并高频刷新；相同页的旧索引结果在刷新中保留，不用旧页冒充新页。
- 万级根目录/子目录、深链接、无请求缓存重开、滚动恢复、默认收起、错误重试、浅色与窄窗验证通过。
- 日常库只读 SQLite 快照：2,356 条媒体、3 个根目录。暖查询中位耗时：首屏 4.315ms、末页 3.334ms、收藏 6.246ms、分辨率 4.395ms、根目录元数据 3.262ms、目录页 4.135ms。未扫描、播放、生成封面或读取源视频内容；不是磁盘扫描/浏览器渲染/跳播性能测试。报告 `build/index-snapshot-dd9dbb04.json`。
- 更新下载卡片复用主题变量、图标与按钮；帮助同步纯净播放、鼠标规则和两种便携包用法。成功 Toast 使用 check 图标、主题成功色与 polite status，仍按既有四秒消失；失败保留 alert，不会被旧成功计时关闭。新检查会清理旧的打开下载失败信息。
