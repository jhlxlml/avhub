# 第六批：独立封面任务、数据库响应与失败截图

按用户批准的 1 → 2 → 3 顺序实现。源码版本仍为 0.2.0 / API 2；不接入 MPV，不重做随机跳播，不打包 EXE。

## 1. 扫描与封面彻底分离

- 元数据扫描不再启动/等待自己的截图线程。发现、探测、索引结束即为扫描完成，目录管理可以解锁。
- 本地服务生命周期拥有单独的单工作者；队列保存在 SQLite，暂停/恢复与扫描取消互相独立。退出取消当前解码但保留待处理项；重启按持久暂停设置继续。
- 当前文件页、剧集页及所选播放视频优先；不会为每张图片轮询、自动循环失败重试或一口气启动多个 FFmpeg。
- 顶栏只增加相机状态图标，点击才展开任务及分页失败详情；设置内提供暂停/恢复。不会增加常驻大横幅。
- 后台图片发布只更新封面版本，不重新加载整张媒体列表，不重启播放或覆盖元数据草稿。剧集占位也能随截图完成更新。
- 离线任务延后尝试并保留，不将离线误报成永久解码失败。源变更、目录移除/重新定位、备份恢复及新重试以指纹和任务代次拒绝旧结果。图片先写临时文件，再原子发布；已有可用图片和手动封面保留。
- 扫描用的 FFprobe/FFmpeg 同样纳入单进程 Windows 退出保护；取消、超时和保护建立失败后，输出管道清理最多等待 2 秒、强制结束后再等 1 秒，不再无限等待 `communicate()`。不扩大原有扫描超时、不终止其他应用的编码器。

扫描状态中的“取消”只取消索引；暂停截图从相机图标或设置操作。封面失败不再计为元数据扫描失败，而在独立任务中说明。

## 2. 数据库响应

原先读查询与写入均经过全局 `DB_LOCK`。现将媒体分页/搜索、目录树、同目录视频、媒体记录和封面状态读取切换为 `mode=ro`、`query_only` 的 WAL 快照。总数和页数据依然在同一读事务；并发读互不阻塞。写入、封面读取/发布及需要迁移的旧库接口仍保留原有保护，不随意移除所有锁。

恢复数据库使用独立的读写门：阻止新读并等待已开始的读结束，再替换索引。源目录/缓存的发布保护与数据库锁采用一致顺序；不把 FFmpeg 解码放在锁内。

只读数据库 URI 统一编码，应用目录含空格、中文、`#` 或 `%` 时也读取正确文件，不因 URI 被截断而误创建另一个数据库；备份校验与恢复同样处理。

诊断保留最近 512 次数据库操作，区分串行事务与只读操作，记录锁等待、连接、事务体（含查询/取行）、提交、关闭与总耗时。另保留最近 32 次超过 100 ms 的操作及时间/线程，避免大量快速操作把刚发生的长尾挤掉。它不是逐条 SQL 分析器，也不包含视频源名称或 SQL 参数；设置中的运行诊断可导出详细分阶段统计。

使用复制的 1982 条真实索引，而不是日常数据库。最终构建受控测试持有写锁 400 ms 时，旧查询约等待 408 ms，新查询约 1.2 ms 返回，这是锁隔离验证，不是实际磁盘扫描耗时。

对分布于真实索引中的 200 源文件，以“旧 → 新 → 新 → 旧”顺序重新探测四次，两种策略各统计两轮查询：旧查询 p95 9.928 ms、最大 139.400 ms；新查询 p95 7.671 ms、最大 20.848 ms。新查询中位数 2.444 ms 高于旧查询 1.537 ms；热缓存、运行顺序和系统负载仍有影响，不能把最大值差异当成精确加速倍数。普通小事务负载下两者 p95 约 1.5–1.7 ms，未声称所有查询显著加速。

**本轮没有重现历史约 3 秒长尾，不能确定它当时全部来自互斥锁，也不能承诺已根除一切长尾。** 已移除明确的扫描读写锁竞争路径，并保留分阶段证据，后续若再发生可区分等待、事务或关闭耗时。本轮没有增加 FFmpeg 并发或查询超时来掩盖问题。

## 3. 单张封面重试及真实 AV1 修复

- 播放页“编辑媒体信息”新增截图秒数，留空自动选择；可单张重新生成，不必重扫全部目录。
- 时间必须为有限非负数且小于已知时长；指定时间失败不会偷偷切换到第一帧。旧自动截图仍可回退第一帧。
- 失败保存 FFmpeg 原因及时间，分页按需查看；源路径在 FFmpeg 原因中替换为占位。明确提示“截图失败不代表视频无法播放”。
- 原来失败的隔离索引 ID 294：AV1、1920×1080、2672.289 秒。单帧解码到空输出成功；真正复现 JPEG 生成后发现 `swscaler` 不接受 `csp:bt709 prim:reserved trc:reserved`，不是简单认定原文件损坏。
- 只有截图出现这个明确错误组合时，才在临时滤镜链修正无效 BT.709 色彩标记再尝试。不会统一把有效 HDR/广色域映射成 BT.709，不更改源文件、技术记录或播放转码策略。
- 修复后自动时间、0 秒、120 秒三次均输出有效 JPEG，单次约 0.20–0.27 秒。没有用这三次截图代替该视频的浏览器长时间播放验收。
