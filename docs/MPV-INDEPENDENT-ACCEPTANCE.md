# 可选独立 MPV 窗口

## 使用与范围

设置 → 播放偏好 → 播放引擎选择 MPV，再将“MPV 播放窗口”改为“独立窗口 · 试用”。仅之后打开的视频生效，默认仍为内嵌模式。开发启动命令为 `npm run electron:dev`。

独立模式只保留一个 Electron 媒体库窗口，MPV 自己创建播放窗口，使用应用自有 Lua/ASS 控制栏，不创建 Electron 视频宿主或透明控制窗口，也不再叠加默认 OSC。媒体库显示随主题变化的紧凑播放状态卡，支持恢复最小化窗口、保存截图、返回媒体库和显式切回现有播放器。恢复按钮不承诺绕过 Windows 的前台焦点限制。

原生窗口采用 AVHub 蓝灰强调色、线性矢量图标和半透明深色按钮，保持亮色画面上的可读性，不绘制整块渐变或控制栏明边框。顶部提供紧凑标题、拖动区域及置顶/最小化/最大化/关闭，置顶位于最小化左侧；底部进度条贯穿可用宽度，设置浮层收纳倍速、音轨、字幕、字幕延迟与旋转。视频叠加控件在浅色、深色媒体库主题下都使用适合画面的高对比配色。

悬停顶部或底部控制区时保持显示；移开后隐藏，暂停和播放行为一致，普通键盘操作不唤出控件。鼠标移动时由 MPV 保持鼠标可见，控制区悬停时关闭自动隐藏鼠标。拖动进度只预览目标，释放后提交一次精确定位。截图使用同样风格的短提示，成功后自动消失，不唤出已隐藏的整套控制栏。

MPV 窗口操作：

| 操作 | 功能 |
| --- | --- |
| 空格 / K | 暂停、播放 |
| ← / → | 后退、前进 5 秒 |
| J / L | 后退、前进 10 秒 |
| 鼠标前进 / 后退键 | 使用 AVHub 已保存的鼠标跳播步长 |
| ↑ / ↓、滚轮 | 音量调整 |
| M | 静音 |
| C | 保存截图到 AVHub 设置目录，无保存对话框 |
| F / 双击画面 | 切换 MPV 窗口全屏 |
| Esc | 退出 MPV 全屏，不关闭应用 |
| PageUp / PageDown | 交给 AVHub 队列选择上一条、下一条 |
| R | 视频旋转 |
| Q / 窗口关闭 | 关闭本次播放并保存进度 |

原生 ASS 控制栏与 AVHub 内嵌控制栏共享视觉语言，但不是同一套渲染器；纯净播放、按指针缩放、拖动画面、应用内画中画不自动映射到独立窗口。回到媒体库窗口后，不把普通页面按键转成后台 MPV 操作。

## 原画与文件安全

- 使用相同 MPV 可执行文件、GPU 后端、硬件解码、缓存上限和 `hr-seek=yes`；没有视频/音频转码、降分辨率或颜色转换回退。
- 保留原有 HDR、高于 8-bit、色彩无法验证的拒绝入口，不因窗口模式改变而绕过。
- 进度、音轨、已识别字幕和延迟仍写入 AVHub SQLite；全局音量和受支持倍速与单视频记忆分离。原生控件产生非 AVHub 支持的倍速时不会污染便携设置。
- 继续通过可信桌面接口获取原文件读取租约。截图结束且 MPV 进程确认退出后才能释放保护；退出失败保留会话和保护，允许重试。
- 禁用 MPV 默认键位、用户配置和脚本自动加载，显式加载应用编译产物内的固定控制脚本及白名单 input.conf，二者均生成在所有权校验的会话目录、退出后清理。视频标题仅作为数据传入并转义 ASS 字符，不拼接命令或脚本。常规属性/鼠标更新合并至 30Hz，点击即时命中；隐藏且无提示时不重复绘制，无常驻动画轮询。关闭拖入换片、自动拼接播放列表、外部引用和在线解析；不会允许原生窗口绕过媒体库换入任意新文件。MPV 进程本身不等于安全沙箱。
- C 仅触发 AVHub 原分辨率 PNG 服务；默认 MPV 截图和 watch-later 落盘入口不启用。截图暂存沿用目录所有权、像素/文件大小、空闲空间检查，发布后清理。

## 应用内验证

`node electron/test/native-independent.mjs` 使用实际 Electron 媒体库入口和隔离生成样本，覆盖设置保存、无多余 Electron 窗口、原生控制配置、暂停精确跳播、播放后时钟继续、C 截图目录与 PNG 尺寸、全屏进退、自动连播、Q 退出、配置临时文件清理及源文件哈希/时间不变。

原生按键由测试专用主进程挂钩注入 MPV `keypress`，验证 input.conf 路径，不是物理键盘/鼠标或桌面合成画面验收；生产 IPC 不暴露该测试命令。结果：`build/native-independent-9CGoys/acceptance.json`，还覆盖直接退出正在播放的 AVHub：renderer-save-complete、native-independent-closed、backend-stopped、shutdown-complete 顺序正常。确定性协调测试为 `electron/test/independent-coordination.mjs`，覆盖保存合并、截图关闭顺序、进程退出失败保留保护、失败启动重试、字幕白名单和设置校验。

补充回归：原有内嵌完整验收 `build/native-player-${pause}-W9Vwz5/acceptance.json`、真实应用流 `build/native-app-flow-o2W6h0/acceptance.json` 通过；启动失败恢复用隔离生成样本验证通过。明确标记的渲染器组件夹具 `native-player-controls.spec.ts` 与 `native-launch-lifecycle.spec.ts` 共 20 项通过，包括独立模式不发送嵌入布局、旧状态修订不能覆盖新进度。后端原画/读取保护与每视频记忆共 12 项通过。

自绘 UI 应用内回归见 `build/native-independent-kWYh7F/acceptance.json`：通过 MPV 原生鼠标/按键事件验证真实 Lua 命中区域、置顶、设置、倍速、字幕延迟、全屏、拖动一次提交、悬停保持、键盘不唤出、截图提示自动消失、正常退出不误报和文件保护。内嵌模式应用流补查见 `build/native-app-flow-u8fd4N/acceptance.json`，解码定位队列、协调与退出失败测试也通过。

未通过的补充项：`native-player.mjs` 的无 viewport 旧 Electron 宿主夹具在纯净模式置顶断言失败。`pure=true`，`always-on-top-changed(true)` 已触发，但 `BaseWindow.isAlwaysOnTop()` 持续返回 false，等待 5 秒也未改变；`build/native-player-${pause}-u5v8zf/` 有失败快照。它不等于当前生产入口的应用内嵌模式，也不是独立 MPV 窗口；本轮不将该夹具计为通过，不修改状态 getter 或将置顶事件冒充 OS 置顶证据。单独保留后续核查，未引入未经验证的旧宿主几何/置顶改动。

实际桌面交互使用隔离合成彩条样本，观察普通及最大化窗口中的文字、图标与菜单，实测进度条点击、设置按钮、C 截图、最大化/还原及关闭。`build/native-app-interactive-ew3Ue1/` 保存只读观察记录；实体 C 键产生 640×360 PNG，日志编码/发布合计约 46ms，关闭后无连接错误提示。该样本尺寸很小，不将截图耗时推广到 4K/8K；跨屏 DPI 与所有显示器配置仍不视为已验收。

正常 Q/窗口退出时，Windows 可能先断开命名管道，再报告进程退出，且不一定收到最后的 shutdown 事件。现在保留读取保护、最多等待 150ms 获取 OS 退出证据；正常退出不误报，未退出或异常退出仍报错并执行受控清理。该等待仅用于退出分类，不介入播放或跳播。

## 同机原画对照

`node electron/test/native-presentation-performance.mjs <只读索引绝对路径> 1 62 2358`

结果：`build/native-presentation-performance-MRsUQ3/acceptance.json`。复制索引、关闭后台封面任务，交替测试模式，每个样本每模式 3 次打开、9 次暂停跳播；同一精确 time-pos 指令，验证 playback-restart、目标时间误差及恢复播放后时钟继续。UI 负责打开/关闭，定位命令经测试主进程注入，排除两种控制栏输入方式差异，因此不是物理点击端到端测试，也不是冷盘或屏幕光子延迟。

| 只读样本 | 内嵌打开中位数 | 独立打开中位数 | 内嵌跳播中位数 | 独立跳播中位数 |
| --- | ---: | ---: | ---: | ---: |
| 4K VP9 MKV | 1958 ms | 1207 ms | 597 ms | 591 ms |
| 4K H.264 TS | 929 ms | 914 ms | 92 ms | 61 ms |
| 4K AV1 MP4 | 913 ms | 888 ms | 280 ms | 280 ms |

全部使用 D3D11VA，保持原分辨率、每会话 sourceLoads=1，未观察到 paused-for-cache，定位误差小于 0.01 秒。短测、系统负载和缓存状态会影响结果，不与之前不同批次测试混算。

结论：独立窗口减少窗口合成与启动协调，但无法消除编码长 GOP、容器索引和解码回溯成本；本轮 MKV/MP4 定位并未显著提速，TS 有小幅改善。保留可选模式，不作普遍性能承诺或默认切换。尚需真实键鼠、跨屏 DPI、长时间及本机主观体验验收。
