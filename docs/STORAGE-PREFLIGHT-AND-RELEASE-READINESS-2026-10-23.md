# 存储预检、保存诊断与发布收口

本轮仅源码迭代与隔离验收，不打包、不发布、不推送标签、不升版本。最终构建为 `4bb2189b5d4e71b0`，版本保持 0.2.15；冻结网页归档和用户原视频不变。

## 存储并发修复

此前 `/api/storage` 在播放锁内遍历数据目录并读取回滚 SQLite；确认清理还会在独占恢复门内重复这些重型检查。受控慢预览可以稳定复现播放锁不可取得。

- 统计与清理预检只短暂采样活动播放 token。全量缓存遍历、回滚数据库读取不再持有播放锁或数据库写锁；恢复共享门仍保护数据库文件不被替换。
- 确认阶段保留扫描、封面发布、数据库写入与封面读者屏障；重新核对当前源路径/封面/待生成任务引用摘要、不可变回滚清单指纹及活动播放 token，不在临界区重新遍历整个缓存或打开回滚 SQLite。
- 最终原视频 Range 读取不经过独占恢复门，也不因清理批次持有文件服务锁而排队。受控删除等待测试验证读者能在删除等待期间完成。
- 预览 token 同时绑定文件大小、mtime、文件身份、数据库引用与回滚证据。同大小同时间的替换文件也会令旧预览失效；最后删除前再次检查身份及封面 pin。
- 新出现的源引用、封面引用、任务、回滚副本或读者均受保护。观看进度变化不触发无意义的清理失效。

边界：最终必要的引用核对、路径验证、unlink 与空目录移除仍有系统 I/O，且删除阶段保留播放控制/写入屏障；不宣称所有清理操作永不阻塞控制请求。实际延迟须继续按缓存规模和磁盘状况测量。本次没有取消安全校验来换取速度。

## 保存长尾诊断

慢操作的异步现场捕获原先只传数字耗时，丢失触发它的操作类型与关联号。本轮改为传递该事件的独立快照，保留操作、连接、scope、提交结果与时间区间。每次串行事务记录排队起点及提交开始/结束的单调时钟时间，便于与后台事件关联。

仍保持固定代码标签、有界记录、异步限频捕获；不记录 SQL、视频路径或标题。不改变 FULL 同步、检查点策略、提交成功语义、重试逻辑或导航等待。
