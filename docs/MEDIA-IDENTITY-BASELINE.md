# 文件身份与桌面性能基线

## 文件身份

扫描以卷标识、文件标识、大小及纳秒修改时间建立身份；这些整数仅在后端及数据库内处理，不经过 JavaScript 浮点转换。源文件只读，应用不会为身份识别重命名、移动或复制视频。

只有已建立基线、同盘固定 NTFS、唯一匹配、旧路径不存在（或仅大小写变化）、原登记目录可访问及非硬链接的文件才自动关联外部改名。同目录外挂字幕保留关联，不改名或复制。手工标题保留；仍为自动文件名标题时随文件名调整。跨盘复制、多个匹配、旧路径被另一文件占用、未建立基线或无法访问时不自动合并。

同一路径的身份、大小或修改时间发生变化时暂停该索引的播放与文件操作，保留旧个人信息，进入“来源变更待确认”。用户可以明确确认仍是同一视频而保留信息，或重新收录为新 ID。新 ID 不继承旧收藏、进度、标签、评分或片单；旧个人信息留在数据库的来源历史中，视频不备份。缩略图重新生成；选择保留信息时，手工封面保留。

确认前与探测后都校验文件身份，页面签名过期或探测期间再次变化则拒绝提交。原文件完整身份返回原位置时解除隔离并保留原数据。处理来源只写媒体库，不要求源目录的文件修改授权。

旧索引第一次扫描建立基线，不追溯判断基线建立前是否已经发生替换。未初始化技术信息的旧记录可正常首次探测；已有技术信息且已变化的旧记录需要确认。身份和时间不是全文件哈希：刻意在原文件上覆盖内容且保留全部元数据的变更不保证识别；不会为每次扫描读取整个视频。

## 状态与权限

- 文件异常状态分别指向回收记录或来源确认，不使用不适合的“核对恢复”按钮处理来源替换。
- 预检期间停止显示“未执行”，不触发确认或文件操作。
- 失败记录按回收记录 ID 定位到实际页并聚焦，重试仍只作用当前页，避免同名文件或跨页范围误解。
- 永久删除独立授权、默认关闭。旧回收授权不继承永久删除权限；每次永久删除及失败重试仍需确认。授权更具体的子目录优先，重新定位/备份恢复后重新授权。

## 性能基线

使用 `electron/test/desktop-library-baseline.mjs`，将现有数据库以只读 SQLite 备份方式复制到独立 TEMP 配置。克隆中仅保留已授权 `E:\downloads` 的 2181 条媒体元数据；禁用扫描与缩略图任务，不复制封面、不读取视频内容。原数据库与源视频不变。

本机一次开发版真实 Electron 测量：新配置首次启动至首屏约 1038 ms，同配置再次启动约 901 ms。分类切换从实际点击事件到相符查询数据的 DOM 提交，首次未缓存约 59–60 ms，缓存命中约 2–5 ms。另记录自动化全程等待（约两秒），不把驱动等待误判成应用查询耗时。

这是元数据界面基线，不是播放、视频跳播、封面解码、打包 EXE 解压或操作系统冷缓存测量；未清系统缓存，也不据此声称所有设备启动均少于一秒。首屏阶段日志区分后端启动、后端就绪、窗口创建、渲染加载和媒体库就绪。

基线复测需要用户授权的索引路径：`node electron/test/desktop-library-baseline.mjs <absolute-library-db>`。真实身份验收：`node electron/test/media-identity.mjs`；只使用测试生成的隔离 TEMP 样本，验证外部改名、替换隔离、明确重新收录/保留信息及视频/字幕哈希。
