# MP4 显式无损按需封装验收

## 变更范围

- 现有 Chromium 播放器默认仍为原片优先，不根据丢帧自动切源。
- 对 H.264 MP4/M4V/MOV，画质菜单增加“原画 · 无损封装（本次）”。
  仅 AAC/MP3 或无音轨可选。每次打开视频重新默认；不增加全局强制封装开关。
- 选择时保留位置、暂停/播放、倍速等状态，主动切换会重建一次源；后续已有
  索引范围内的跳播复用该源。返回原片及进入此选项均撤销有损转换权限。
- 复用既有原编码按需分片，没有整片副本，没有重编码或缩放。失败提供返回
  原片入口；不通过隐藏等待或保留旧画面声称加速。

## 整片复测发现与继续迭代

第一次实际接入整片测试（构建 ac83f9c4fbe576e3）暴露了旧索引器的负收益：
它逐包扫描整片，异常交织 MP4 约 30 秒后索引超时并退到普通封装，远跳未
通过。失败报告 `avhub-chromium-direct-5Wh7ha/performance.json` 保留；原视频
未变、正常退出。没有把这次测试写成通过或发布正式标签。

为避免只缩短提示，增加 `app/mp4_timeline.py`：

- 跳过 mdat，读取 classic MP4 的 stts/ctts/stss 等样本时间表，支持 64-bit
  顶层区间；以 FFprobe 首部 8 包校验实际解码时间偏移。
- 元数据最多 16 MiB，单表最多 250,000 项、样本最多 3,000,000；取消、
  截断、异常计数、重复字段及时间戳不一致均拒绝猜测。
- 复杂编辑列表、裁剪/变速、多编码描述、负 CTS 导致独立 DTS 偏移、fragmented MP4 等走既有探测路径。
  不是任意 MP4 解析器，不承诺所有结构都快速索引。
- 索引继续绑定源路径、大小、mtime；生成期间源变化不发布索引或分片。
- 单分片生成有硬容量上限（最多 256 MiB，低目标保留一个受限 GOP），预留
  64 MiB 磁盘余量；达到上限的输出不当作成功分片发布。已有分片在低空间
  时仍可读取，活跃读者的原保护、取消和退出清理保持不变。

另通过真实容器夹具发现并修复一处质量问题：只保存在 MP4 `colr` 中的色彩
标记不会随普通 TS stream-copy 自动保留。现在读取原始 nclx/nclc 数字 CICP，
通过 H.264 元数据位流过滤将同一标记写入 VUI，不解码/重编码切片、不做色彩
转换。容器中没有标记时不补 SDR 默认值；ICC、未知或无法表示的描述拒绝
封装。索引和普通无损路径均应用，旧 MP4 时间索引仍复用，只补读有界色彩头。

SDR/8-bit 和合成 PQ/10-bit 样本的原尺寸、像素格式、色彩字段及原关键帧
YUV 解码像素一致。合成 PQ 不是实际 HDR 视觉验收。显式“本次”选项失败后
停止并提供返回原片，不再偷偷回退到另一种可能未验证的封装路径。

首部包数探测语法依据 [FFprobe 官方说明](https://ffmpeg.org/ffprobe.html)；
时间表结构参照 [QuickTime 文件格式](https://developer.apple.com/documentation/quicktime-file-format)。
