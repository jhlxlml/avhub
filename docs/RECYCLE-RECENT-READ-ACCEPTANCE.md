## 本轮处理

- 等待点击最近回收发出的那一个真实 GET 响应，要求 HTTP 200、正文完成、
  精确操作 ID 唯一且状态 available，再分别验证 UI 渲染与真实恢复结果。
  不用额外读取轮询替代该请求，不隐藏 loading，不接受错误/空数据作为成功。
- 生产读取期限仍是 15 秒；测试响应/正文等待有明确上限，渲染另外有界。
  不全局增加 Playwright 超时，不自动重试恢复、回收或其他写操作。
- 每次验收记录有界 HTTP 状态/完成耗时/传输错误、阶段、异常与样本哈希结果；
  失败保存生成样本画面。失败清理仍只恢复日记中唯一匹配的自建样本，不清空
  系统回收站，也不触发永久删除兜底。
- WindowsRecycle 记录最后一次请求的锁等待、启动、IPC 和总耗时，以及活动
  阶段；RecycleRecords 记录枚举、身份建表、缓存命中和等待耗时。记录只保留
  一份，无路径、标题、文件身份或原始错误文本；已有锁、60 秒桥接期限、缓存
  TTL、异常关闭及不重放语义不变。失败刷新不覆盖之前可用的完整快照。
- CI 增加 6000 ms 的一次读取延迟注入，仍调用实际 API 和原生恢复。该延迟
  是测试注入，不是原生 Shell 速度，不作为性能优化证据。报告同时进入失败
  附件和成功候选的计时附件，便于下一云端读取真正慢在哪个阶段。
- 共享源码验收入口支持 --from-step，从指定失败步骤执行其后所有源码验收，
  不包含打包或发布，避免只复测一个失败用例又漏掉后面未执行的组。
