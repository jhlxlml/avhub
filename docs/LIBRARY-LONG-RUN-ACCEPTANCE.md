# 大媒体库持续运行验收

## 范围与实现

桌面端真实 Electron，正常硬件 GPU；只读复制现有索引与封面到测试拥有的 TEMP
目录。原始视频不复制、不修改。测试库包含 `E:\downloads` 下 2,178 个视频及封面，
播放样本为用户授权的 3840×2160 MKV（索引 ID 196，约 675 秒）。

新增封面 ETag 条件校验：当前版本地址沿用五分钟私有缓存；缓存过期后，未改变
的图片可返回 304 空响应。旧版本地址仍需校验，失效图片返回 404/no-store。
自定义封面在 304 路径也释放文件句柄；不改变视频、音频或播放链路。

## 测量方法

`electron/test/desktop-cover-stress.mjs` 支持持续时间、跨页遍历、实际 MPV 开关、
每分钟检查点及测试目录内的停止标记。播放与媒体库交替，同一个 renderer 文档
在开关播放后保留；禁止通过 reload、强制 GC 或清空全局缓存制造内存回落。

- 每页最多 96 张卡片，记录附着图片数、解码像素、JS 堆和各进程工作集/CPU。
- CDP 分别记录逻辑请求、HTTP 实际传输、缓存命中和 304；传输量不是磁盘 I/O。
- MPV 每轮实际播放、暂停后跳播，核对定位误差、源加载次数、缓存等待与丢帧。
- 第一轮保存跳播前后的原尺寸 PNG，验证画面哈希变化，不以进度数字代替解码。
- 返回媒体库后验证解码进程退出、原生窗口销毁及显示监听器不累积。
- 正常结束核对原视频 SHA-256、大小与 mtime，验证无残留 MPV。
- GPU 进程工作集不是显存；采样工作集不是严格内存上界或无泄漏证明。

```powershell
node electron/test/desktop-cover-stress.mjs D:\AI\codex\avhub\AVHub-data\library.db --seconds=3600 --hardware-gpu --walk --playback-id=196 --playback-every=10 --stop-file=D:\AI\codex\avhub\build\library-hour.stop
node electron/test/summarize-library-soak.mjs <测试输出的绝对路径>\library-soak.json
```

停止标记仅支持项目 `build` 内的明确路径；标记存在会在当前轮结束后停止，报告
仍明确记录 `targetReached:false`，不能算完成计划时长。运行期间不要重建应用。

## 中断保护与后台运行

测试每分钟原子保存 `checkpoint.json`，保留此前全部样本及已完成播放会话；
检查点始终为 `incomplete:true`、`targetReached:false`、`cleanExit:false`，
只有最终报告完成源身份核对与退出清理后才可作为完成证据。保留旧检查点不会
把两段运行拼成一小时连续验收。`progress.json` 只是最新一条摘要。

Windows PowerShell 可用独立后台启动器运行，隐藏辅助控制台，不注册服务或计划
任务。Electron 测试窗口仍可见，使用隔离数据，不是日常媒体库实例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File electron/test/start-library-soak.ps1 -IndexPath D:\AI\codex\avhub\AVHub-data\library.db -MediaId 196 -Seconds 3600
```

启动器返回本次唯一的 `run.json`、stdout/stderr 和停止标记路径，输出在项目
`build/library-soak-run-*` 中；stdout 首行指出实际 TEMP 报告目录。查询状态时优先
读取报告，不根据旧 PID 猜测进程身份或强杀进程。关闭电脑、退出系统仍可能中断
后台测试；不能保证系统中断后自动续跑。最终验收需要一次不中断的完整运行。

## 内存短对照

同一构建、相同 96 张封面页、正常硬件 GPU，顺序运行两组，不重载实验文档，
不执行 GC/清缓存；在原有采样上增加私有内存、DOM 节点/监听器和 embedder 堆。
这些诊断只读，生产代码与播放参数没有改变。

| 场景 | 实际时长 | MPV 会话 | renderer 首尾 MiB | 私有内存首尾 MiB |
| --- | --- | --- | --- | --- |
| 固定页反复滚动 | 186.7 秒 | 0 | 172.2 → 158.4 | 102.4 → 86.7 |
| 同页滚动并开关 MPV | 200.3 秒 | 9 | 167.6 → 217.7 | 98.1 → 140.4 |

报告分别为 TEMP 下 `avhub-cover-stress-g4v5tC/library-soak.json` 和
`avhub-cover-stress-w2G8Ek/library-soak.json`。两组均达到时长、正常退出、错误 0。
视频组原文件身份校验通过；纯封面组没有播放视频，不做视频结束哈希校验。

两组文档计数均由初始 4 回落到 1，节点首尾分别为 5,998→3,442 和 5,998→3,829，
embedder 堆由 24.9→16.3 MiB 和 23.5→15.2 MiB；初始计数包含正常初始化所留的
待回收文档。所有视频会话结束后仅余一个主窗口、显示监听器 0。没有发现随这些
会话次数单向累积的节点/窗口证据，但不能据短测判定零泄漏。

视频组仍有私有内存增加，尚不能归因于哪一种缓存或原生生命周期。两组还存在
首次播放器初始化、采样次数与开关操作等差异，不能把首尾差直接解释为每次
打开都泄漏固定内存；也尚未排除 CDP/Playwright 诊断自身的保留开销。

若要额外核对节点与监听器，可对该测试的 `profile` 运行
`node electron/test/read-library-counters.mjs <测试 profile 绝对路径>`。它只读取
`Memory.getDOMCounters` 和 `Runtime.getHeapUsage`，不调用会触发 GC 或清缓存的
`prepareForLeakDetection`；只对比同一界面阶段的数据。

2026-10-17 的中断长测首段同时运行了独立后端、UI 及桌面回归，存在额外
CPU/GPU 负载。后续完整小时测量独立运行，也不能视为受控冷盘基准；其开播
判定包含测试轮询等待，不能当作纯解码首帧计时。

## 验收边界

单机、单个真实 4K 样本；封面悬停预览关闭，未同时扫描原媒体目录。浏览器测试
只是明确标记的 renderer/HTTP harness，不是浏览器产品验收。物理多屏混合 DPI、
HDR、长 HEVC 仍未验证；当前只有一个 125% 显示器。小时测试也不能代替这些项目。

## 下一步顺序

   并控制网络诊断的采样开销，继续定位 renderer 私有内存上涨；确认归属前不
   盲目调整全局缓存预算。
   已完成的额外采样开关/自然静置对照及按需诊断入口见
   [播放开关内存隔离诊断](PLAYBACK-MEMORY-ISOLATION.md)，根因仍未确认。
2. 用户实机验收物理多屏混合 DPI、全屏/纯净模式切换、最小化恢复；异常时保留
   最近布局与屏幕图像证据。另保留一次未定位的 MPV 启动超时，不提前宣称根治。
3. 在前两项稳定后扩大真实格式样本，分开测量冷/热启动和准确跳播，不用隐藏
   缓冲提示或质量降级代替流畅度优化。
