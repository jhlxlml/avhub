# MPV 原生播放试用

## 当前定位

Windows Electron 的可选播放引擎，不是新增网页版，也不是默认替换现有播放器。
在设置 → 播放偏好选择 MPV 后，仅之后打开的视频使用原生解码；默认使用播放页内嵌的原生视频区域，也可选择独立 MPV 窗口。独立窗口的交互与验收边界见 [独立窗口说明](MPV-INDEPENDENT-ACCEPTANCE.md)。原有 Chromium
原文件直放 / 无损封装保持不变；失败不会自动降画质、静默转换音轨或反复切引擎。
媒体页可明确选择“切换现有播放器”，关闭原生进程后再切回，并重新读取已保存进度。

本轮是源码开发试用，未打包、未发布、未增加版本号。HDR、高于 8-bit 的原生显示
未验收，入口会拒绝并解释原因，不能以默认 HDR→SDR 映射充当兼容优化。
现有播放器的画中画尚未迁移。原生窗口已有系统字幕文件选择和文字字幕外观设置，
ASS/SSA 保留原排版；外观与现有播放器共用保存。完整待播队列复用媒体页界面，
原生控制栏的片单图标展开当前播放页队列，不再弹出另一播放器窗口。
两套引擎共用视频级音轨、已识别字幕与延迟记忆，按源身份与轨道信息校验。
保存的是 FFmpeg 绝对流索引，而不是 MPV 分类型轨道 ID；实际轨道发现后、正式播放前恢复。
选择不匹配时不猜测、不重编码；源文件或关联字幕变化后旧记忆失效。
全局音量/倍速/字幕外观独立保存。媒体库以外的临时导入字幕、关闭音轨为会话内操作。
尚未把两套解码链合并成一个完整状态机；不以共用记忆表示所有功能已经完全等价。

## 运行

```powershell
npm run prepare:mpv
npm run electron:dev
```

准备脚本只在主动执行时联网。下载官方 mpv GitHub CI 的完整 Windows x64 构建，
校验固定归档 SHA-256 后，还分别核对 EXE 与许可文件摘要，只提取 `mpv.exe` 和
`LICENSE.GPL` 到忽略提交的 `bin/mpv/`。唯一输入清单为 `electron/mpv-runtime.json`。
应用启动、播放不联网、不搜索 PATH、不接受渲染器自定义可执行文件或命令行。
缺失运行库时显示不可用，现有播放器不受影响。

当前试用运行库：

- 上游提交：`7c4f662c0`，官方工作流运行 `38598545310`。
- 资产：`mpv-v0.41.0-dev-g7c4f662c0-38598545310-x86_64-w64-mingw32-full.zip`。
- 归档 SHA-256：`0c310aa06b77bbf603ca99b024f0cbd5d85bbceb4c106235373d844dbda941ec`。
- 提取 EXE SHA-256：`b294a778f57b2d706e9a3c65a912130e3f5544a8b34708b67a47b59a6cbb6ff2`。
- 来源：https://github.com/mpv-player/mpv/releases/tag/git-release
- 构建上下文：https://github.com/mpv-player/mpv/actions/runs/38598545310
- 原生运行库 EXE 约 150.6 MiB，下载 ZIP 约 61.9 MiB；不是最终安装包增量测量。

官方 `git-release` 为滚动资产，不能当作永久稳定下载地址。资产变更/下架时准备脚本
必须明确失败，不能跳过摘要或自动下载其他版本。正式发布前需重新选定持续可取的
发行输入、整理完整第三方许可及对应源码/构建材料，并验证 CI 的分发资源。
当前默认发布配置没有自动纳入 MPV 运行库，不应把源码试用说明当作已发布功能承诺。
`npm run check:mpv` 离线校验当前二进制和许可摘要；
`node scripts/check-mpv-readiness.mjs --release` 在当前状态下**必须失败**，列出剩余发布门槛。
这不是替代许可审查或可视验收的自动签字。普通 CI 仅验证清单、控制队列和渲染器交互，
不因此声称已在云端验证原生 D3D11 合成或将运行库加入正式包。

## 架构与安全边界

- 独立 MPV 进程负责原文件读取、解复用、解码与 D3D11 渲染；没有 FFmpeg 转码链路，
  不生成视频副本。普通图像缩放/旋转由显示层完成。
- Electron 使用无 WebContents 的 `BaseWindow` 管理解码宿主；透明 `BrowserWindow`
  仅负责 React 控制层。默认入口通过可信 Windows 桥将视频宿主转换为主窗的真实
  `WS_CHILD`。透明控件保留由主窗口拥有、无边框且无任务栏入口的 owned window，
  避免 Chromium 透明窗口改为 WS_CHILD 后合成不透明黑底；不是独立的视频播放器窗口。
  页面通过当前会话同步 DOM 播放区域、裁切及圆角；同一时刻至多一个在途更新，
  只保留最新布局。视频通过 OS 父子关系跟随，控件同步主窗客户区位置、DPI 与裁切；
  最小化隐藏控件，迟到布局请求不得重新显示；滚动裁切避开粘性标题；
  主页面弹窗、菜单和 inert 状态隐藏原生层，关闭后恢复，不关闭或重载解码器。
  DPI-aware 原生调用按父窗口 DPI 换算；混合 DPI 的交互验收仍保留。
  独立宿主仅保留为源码测试/开发回退入口，不作为默认产品界面。
  注意空 BaseWindow 仍会创建 `Intermediate D3D Window`，不能以“没有网页”推断
  “没有合成层”。可信桌面桥在起播、内容区调整尺寸与恢复后校正子窗口层级，
  只把当前 MPV 子窗口置于该宿主的其他子窗口上方，不改变全局置顶或焦点。
  校验有效读取租约、宿主 PID、解码器 PID、直接父窗口和 `mpv` 类名，渲染器不能调用。
  主窗和原生浮层均保持 context isolation / sandbox / nodeIntegration=false。
  **MPV 本身并未因此获得 Windows 进程安全沙箱**；进程隔离用于故障与生命周期管理。
- 每会话随机命名管道、JSON 请求编号、指令超时、64 个在途请求上限、1 MiB 响应上限。
  禁止用户配置与外部脚本加载，不向渲染器暴露原始命令、路径或执行入口。
- 主窗口只能通过已索引媒体 ID 启动；浮层只能控制自己的当前会话。
  主窗不能直接调用 seek 等浮层能力，旧会话不能关闭新视频。
- 源文件在后台持有**不依赖心跳过期**的读取租约，解码器真正退出后才释放。
  播放期间的重命名、回收、索引恢复仍受现有文件服务保护；心跳用于封面让路，
  不能替代源文件读取锁。
- 原生起播先请求封面与无损准备让路；正常播放/暂停状态按现有服务规则更新。
- 进度和音量/静音/倍速按顺序写入原有数据库；退出先保存、停止解码器、释放租约，
  最后关闭媒体服务。保存失败可以重试或明确放弃进度，不能跳过占用保护。
- 关闭前等待已经接受的偏好指令完成，再抓取最终保存快照，避免立即关闭丢失倍速等设置。
- 独立宿主回退保留 Windows `WS_THICKFRAME`；默认嵌入宿主移除顶级窗口边框与
  POPUP 样式，纯净播放、置顶与视频全屏操作现有主窗口，复用窗口状态及退出恢复。
  独立回退的透明浮层仍无边框，按宿主**内容区**对齐，
  不以外框比例代替视频比例。分数 DPI 的实测舍入误差不会反向触发宿主尺寸循环。
  最小化隐藏浮层，恢复重新同步；显示器移除/工作区改变时校正位置，关闭移除监听。
  原因对应 Electron 的 [Windows 全屏实现](https://github.com/electron/electron/blob/main/shell/browser/native_window_views.cc)：
  `thickFrame:false` 使用窗口尺寸模拟全屏，不会进入可被 `isFullScreen()` 正确读取的常规状态。
- 截图使用用户现有截图目录和 C 键；先在有所有权检查及空间检查的临时目录生成 PNG，
  再交原有上传服务校验、发布。不缩放截图、不剥离 cICP 色彩标签、不覆盖原视频。
  点击立即显示保存状态，保存期间禁止重复请求，成功和失败均反馈；原尺寸 PNG
  编码指令单独允许 30 秒，普通控制指令仍为 5 秒，不以降低截图质量换取响应。
  浮层布局避免复用媒体库的语义元素样式，浅色/深色主题均保持透明顶栏与完整尺寸图标。

## 跳播完成与异常

同一时刻最多一个活动跳播，待执行请求只保留最新目标。MPV 的指令应答不是完成：
必须出现 playback-restart，并读取实际 time-pos，目标偏差不超过 0.5 秒才确认。
这不是逐帧精度承诺，也不等同显示器画面延迟的逐像素验收。

长 TS 实测发现解复用偶尔落在目标之后。只有确认过冲时，才最多两次增加该次跳播的
前置解复用时间；成功后归零，正常 MKV/MP4 不统一增加 preroll。纠正耗时包含在本次
定位时间内。超时明确报错，不把旧帧或加载提示的消失当成成功，不偷偷改成关键帧跳播。

起播窗口总显示延迟与 `playback-restart` 不是同一口径。界面分别列出指令执行定位耗时、
含排队的最近跳播耗时、源文件加载次数、缓存等待事件和已结束的缓存等待累计时间。
掉帧使用实际支持的 `frame-drop-count` / `decoder-frame-drop-count`，未知值显示“—”，
不能把未取得的数据当成零掉帧。

旧索引缺少色彩信息时，仅执行最多 5 秒、2 MiB 探测预算和 32 包读取限制的
只读 FFprobe 探测，只输出首个视频流的信息，验证后写入本地索引；不为起播建立全文件索引。超时/未知则拒绝
原生试用，不默认 SDR、不降位深。已有完整元数据不重复探测。

## 后台读取预算

元数据探测和封面解码共享后台准入预算：全局最多 2 个，本地卷保留最多 2 个，
同一 UNC 共享最多 1 个，避免无理由将原有双工作者本地扫描降成串行。
不同卷/共享可绕过等待同一繁忙卷的队首任务；排队可取消、异常释放计数。

原生起播/跳播只让**新**后台任务短暂让路：心跳每次最多续 4 秒，同一次准备最多
15 秒；正常播放/准备结束清除该保留，不能无限饿死扫描。已有封面暂停让路规则保留。
占用心跳按会话顺序提交，最后的退出状态排在之前的状态之后，避免迟到心跳重新登记。
诊断新增 `background_reads` 计数，不保存源文件路径。

这不是全系统磁盘调度器：目录遍历、系统缓存及所有封装/预准备 I/O 尚未统一接入，
不能声称已经实现 Movie 的完整共享读取调度，也不能承诺所有文件零等待。

## 验证与限制

```powershell
npm run test:electron:mpv
node electron/test/native-soak.mjs 120
# 必须显式给出已授权只读索引及媒体 ID；报告写入 build/mpv-real-*。
node electron/test/native-real-media.mjs D:\path\to\library.db 196
```

已完成：

- 前端/Electron 编译；控制队列最新目标、旧重启事件、位置过冲纠正与参数复原测试。
- 后端非过期读取租约、设置白名单、PNG cICP 长度/CRC/原字节保留测试。
- 真实 Electron + MPV 的 H.264 MKV 合成样本：目标定位、原尺寸截图、轨道控制、
  纯净播放置顶状态、滑块点击后空格、主窗口权限限制及原文件字节/mtime 不变。
- 设置/媒体页引擎启动与明确切回 Chromium；原生解码活跃时应用关闭回归。
- 已授权 E:\downloads 的只读克隆索引：4K VP9 MKV、约 7 小时 H.264 TS；
  D3D11 硬解、目标 time-pos 和原分辨率 PNG，原文件 size/mtime 不变。

测量示例（开发机单次结果，不是普遍速度承诺，存在缓存预热）：

| 样本 | 起播 playback-restart | 连续跳播 | 远跳 |
| --- | --- | --- | --- |
| 3840×2160 VP9 MKV | 约 692–699 ms | 约 114–845 ms | 首次到 400 秒约 3912 ms，预热后约 446 ms |
| 1920×1080 H.264 TS，约 7 小时 | 约 686–2952 ms | 约 44–303 ms | 到 400 秒约 4–16 ms，不能视为冷读结果 |

重要未验证项：

- 2026-10-17 已取得主窗口的真实桌面合成画面，并复现/修复透明子窗口遮挡黑屏。
  生成样本的可视证据不代表所有 GPU、多屏 DPI 或 HDR 均已通过；详细报告见验收记录。
- 多显示器、混合 DPI、最小化/恢复/全屏的实际视觉效果、长期运行内存、异常强杀后
  的系统窗口清理，还需交互/硬件验收。
- 不把 MPV playback-restart 和 Chromium requestVideoFrameCallback 当成同一种精确
  显示延迟指标。不同引擎、缓存冷热及测试顺序不同，不能直接声称提升若干倍。
- 探索性 Chromium 对照发现隐藏主窗口的 rVFC 有约 1 秒调度偏差；该轮数据不能用于
  相对提速结论。脚本已要求比较前显示/聚焦主窗口，仍需交互桌面复测与同口径采样。
- HDR / 高位深拒绝原生进入，未完成硬件色彩验收；不宣称支持原生 HDR 透传。
