# 设置/片单样式归属与延长桌面验收

## 范围和构建

- 延续上一轮备份、查询竞态、分批清理修复后的验收，重点增加真实大库的
  Chromium 播放/返回循环和空闲观测，不修改播放策略来追求表面流畅。
- 开发构建：`0.2.16 / 97a95279a0a2f546`。没有升级版本、打包、提交、推送
  或发布；冻结网页归档不变。原视频不修改，真实测试仅使用已授权的
  `E:\downloads` 只读源，扫描及封面生成使用单独创建的测试媒体。

## 样式归属

- 设置和片单样式统一在入口中预加载，排在共享设计系统、Mira 基础规则之后；
  移除 Settings 懒加载模块中的重复样式导入，打开对话框不再改变样式加载顺序。
- 把目录行、权限开关、设置字段、封面任务摘要、备份/存储布局归入
  `frontend/src/settings.css`；把片单摘要、列表、搜索和按钮规则归入
  `frontend/src/playlists.css`，从 `mira.css` 移除相应跨模块覆盖。
- 保留同一套主题变量、Lucide 图标、键盘焦点、危险操作区分和响应式布局。
  主要控件使用共享 32 px 令牌，紧凑目录图标操作使用 28 px 令牌。
  这是两个模块的归并，不代表全项目历史样式已彻底去重。
- 增加样式归属静态契约和深浅色、390/1440 px 的重复开关对话框测试；
  390 px 是明确标记的 renderer harness，不是 Electron 最小窗口验收。

## 测试方法

### 真实大库

`electron/test/desktop-cover-stress.mjs` 现在可以指定
`--playback-engine=chromium`；原 MPV 分支和默认值保留。新辅助模块
`electron/test/chromium-library-cycle.mjs` 只负责验收观测，不参与产品运行。

测试只读复制现有索引和封面到自有 TEMP 配置，过滤为已授权的
`E:\downloads` 条目，关闭该副本的封面生成和文件操作权限。每页最多 96 项，
连续滚动及翻页，每四轮进入一次播放，播放十秒，使用真正的 Space 暂停、
ArrowRight 快进五秒，再点击返回。返回不重载文档，不以重载掩盖资源滞留。

- 首帧及跳播结果使用 `requestVideoFrameCallback`，核对实际画面时间、
  解码尺寸、掉帧、源加载次数，而不是只观察 UI 提示或 `currentTime`。
- 记录 renderer/主进程/GPU 进程工作集、私有内存、JS/嵌入堆、DOM 文档/
  节点/监听器、窗口数、返回后视频元素数；结束后再空闲 60 秒。
- 每分钟写入明确标记未完成的检查点；只有完整时长、源身份复核和正常退出
  之后，最终报告才能标记完成。观测器事件列表有上限，结束时释放监听器和
  帧回调，并有独立的 Node 契约回归。

### 播放/扫描/封面并发

`electron/test/concurrent-soak.mjs` 增加 `--hardware-gpu` 和
`--idle-seconds`。使用生成的 H.264 MP4，持续播放与新增样本扫描交错，定期
申请封面重试，并留暂停窗口让封面真正发布。核对实际解码帧推进、源地址
不变、无源重载、扫描/封面错误、源 hash；返回媒体库后再记录空闲内存和
视频节点。该测试不使用真实用户媒体。

### 环境边界

三组长时验收的部分阶段并行运行；期间存在其他回归负载，不作为孤立性能基准，也没有
修改前后对照。均在真实 Electron 中使用正常 GPU/sandbox 启动参数；为避免
后台测试窗口被节流，测试专门禁止了背景节流并显示窗口但不主动抢焦点。
Playwright/CDP 会附加观测开销；没有强制 GC 或清空缓存。GPU 进程工作集
不是显存占用，工作集不回到冷启动水平也不能单独证明泄漏。额外封面网络
测量关闭，其流量未知，不是零流量。

## 后续边界

本次样本和有界时长不能替代整日播放、多机型、高码率、HDR/10-bit 或混合
DPI 桌面验收。此前用户搁置的特定大 MP4 问题不在本轮重新展开。
偶发启动超时和耐久提交长尾仍保留跟踪，不能由样式回归或本轮有界测试宣布解决。
下一轮优先用相同页集/循环次数、单应用负载做缓存与原生内存归因，验证低内存
环境下的回收与预算，再决定是否调整缓存策略；不以定时强制 GC、刷新页面或
反复卸载屏外图片作为未经验证的优化，避免换来重复请求、解码和滚动闪烁。
