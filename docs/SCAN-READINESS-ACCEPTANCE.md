# 真实扫描就绪机会观测

承接 [纯数据库小批次实验](BOUNDED-SCAN-BATCH-EXPERIMENT.md)。这次运行实际桌面
扫描器和真实 FFprobe，而非实验 SQL 写入器；仍不启用批处理、不等待凑批。
原视频、画质、FULL、自动检查点、保存优先和工作线程数量均不改变。
未访问日常媒体库或 `E:\downloads`，所有媒体源为自建生成样本；不打包推送，
版本维持原值。初期采集构建为 `cdb35d0baa025340`；随后改为默认关闭的诊断，
最终开关对照构建为 `14f0f8faa7865db6`。

## 观测边界

`scan_readiness` 位于本地诊断导出内，使用固定数值/阶段字段，不记录文件路径、
标题、媒体指纹或异常消息：

- `probe_and_budget`：读取预算取得与 FFprobe 调用的合并耗时，不等同于纯探测
  CPU 时间；不包含更早的目录遍历、旧索引/来源身份观察。
- `prepare`：探测返回后的编码/源属性验证及技术元数据准备。
- `ready_wait`：技术信息已验证就绪，至发布门、数据库写锁与连接均取得。
- `write`：获得数据库连接后到真实事务上下文成功退出并唤醒封面工作者。
  它含 SQL、属性复查、commit、close 等，不等于 commit 单项。
- `committed` 只在实际提交返回后记录；取消、失败、未完成分别计数，不将
  探测结束或内存中处理完成当作持久化成功。

详细观测默认关闭，只有启动时 `AVHUB_PROFILE_SCAN_READY=1` 才启用；测试脚本
用 `--readiness=on/off` 显式控制。enabled=false 是未测量，不表示真实等待或
探测耗时为零。关闭时不读观测时钟、不分配活动 ticket、不加统计锁，但仍有
少量空操作调用，不声称绝对零开销。

启用时只记录需要重新探测的文件；未变化文件、单独恢复 missing/root 元数据的路径
不纳入这个 cohort，不能把它当作整个媒体库查询/增量扫描的耗时。

`ready_at_arrival_counts` 包含刚就绪的自己；
`other_ready_at_writer_entry_counts` 在获得写锁/连接时统计其他就绪项，不包括
正在探测或已经写入的项。这是“写锁入口只合并已就绪项目”方案的瞬时机会
上界，不表示已实施批次，也不保证这些项一定能通过最终源/取消校验。
没有测量 SQL 执行中追加记录的方案，更不能据此证明任意管线重构都无收益。

最多跟踪 8 个活动项，超出只跳过观测、不阻塞工作；近期 128 项、最长等待 8 项，
其他只有固定组统计/直方图。记录容量有界，报告不共享内部可变对象。观测不
新增数据库查询或写盘，不改变锁顺序；各线程阶段可重叠，累计耗时不能直接
相加当作扫描墙钟。

## 测试

新增 8 项独立状态测试和 2 项生产扫描集成测试，模拟时钟/并发只验证边界，
不作为播放或性能证据。覆盖容量、隐私、快照隔离、生命周期极值、取消/失败
区分，以及 scope 与实际数据库提交的关联。错误阶段调用只记录诊断异常，
不改变调度；真实验收要求 invalid_transitions / omitted 均为 0。

- 最终完整后端 556 项：555 通过、1 跳过，96.612 秒，包含后补的取消发布计数测试。
- 媒体库切换、进度保存、完整备份、退出、封面任务组件/接口 harness 19 项通过，
  33.9 秒；不将该 harness 冒充桌面验收。
- 前端与 Electron 开发构建、脚本语法及 diff 检查通过；既有 Vite CommonJS
  配置加载/大分包提示不在本轮处理。

## 同构建开关对照与验收脚本修正

初次 OFF 尝试 `z5gode` 因断言错误未完成验收：cover-publish 门进入 602 次、
异常退出 1 次，而数据库发布与完成封面均为 601。取消可发生在进入门后、
进入数据库前，不能把门进入次数等同于数据库提交数。该样本保留为失败证据，
没有作为通过轮次或性能表样本；未修改产品取消/重试逻辑来迎合测试。

新增专项验证“取消一次、随后成功一次”对应两次门进入、一次成功提交。脚本
改为成功门退出数等于完成封面，且总门进入数不小于数据库发布尝试数；原有
行变化、任务完成、持久进度、源文件与正常退出断言均保留。预备 ON 轮 `u3ISNC`
也未纳入下表。修正后重新连续执行同一构建 14f0f8faa7865db6 的 ON/OFF/OFF/ON。

每轮 600 个实体生成视频 / 30 目录，加独立播放源，其他 GPU/sandbox/后台节流、
搜索、保存、封面生成和退出负载相同；新隔离库、顺序运行，不并发其他回归，
期间不修改生产代码。不把此规模直接换算成上面的 1200 文件测试。

## 决定与下一步

**不接入强制 4/8 条合批，不为凑批增加等待，保留逐条原子提交。**目前写锁入口
几乎没有可合并项，不能把纯 SQL 的巨大倍率带入真实扫描。保留可选诊断，
避免为有限机会引入额外管线、取消恢复和首批展示复杂度。

下一步优先补齐暂停保存的事件/请求分段计时，并在真实 Electron 中区分正常
播放、暂停和恢复阶段的帧变化。先确定一次 385ms 异常来自应用还是测试调度，
以及丢帧计数是否对应播放卡顿，再决定修什么；不凭单次异常改 SQLite、解码
或降低画质。探测/预算的分段亦可后续按真实慢扫描需要细化，而非盲目增加并发。

后续分段采集与真实验收见 `PAUSE-SAVE-TIMELINE-ACCEPTANCE.md`。已捕获
不同阶段的长等待，尚不将其归为同一根因；播放中掉帧也保留为未解决项。
