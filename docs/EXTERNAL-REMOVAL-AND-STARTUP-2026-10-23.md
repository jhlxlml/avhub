## 外部删除后的实际行为

不是新增删除权限，而是验证现有“刷新媒体库”的同步路径：

- 目录可访问且完整扫描完成时，未找到的正常视频标为 `missing=1`。
  普通视频墙、收藏、继续观看不再列出；目录统计随查询更新。
- 片单保留成员并标为离线，自动下一条不应选择它；不伪造应用回收记录。
- 原索引、手动标题、收藏、进度及封面引用保留。同一文件移回再刷新，恢复
  同一个 ID，不重复收录。替换成其他文件仍走既有身份变更确认，不擅自继承。
- **不会自动物理删除封面文件**。存储清理也保护当前引用的自动封面、手动
  封面及保留回滚副本。这有利于恢复，但确实会保留缺失视频的缓存占用。
- 整个目录离线、遍历部分失败或扫描取消时，不把未遍历的视频批量标为缺失。

后续可单独提供“失效索引 / 自动封面清理预览”，显示数量和容量，由用户确认。
不能把离线目录视作永久删除，不能自动清除手动封面或个人观看数据。

## 首页按需加载

设置页代码按入口加载；保存、退出、确认、关于等事件宿主保持立即挂载。
原生播放控制继续保留原加载路径，避免在 MPV 接入链路增加异步握手。
共享样式继续预先加载，避免 CSS 插入顺序改变主题布局。
首轮布局回归发现过宽屏设置字段错位，修正加载顺序后深浅色 / 窄宽屏通过。
设置加载等待期间仍可关闭或 Escape，不在代码下载后自行重新打开已关闭弹窗。
模块下载失败不会卸载媒体库；提示重启恢复。不提供无效的同页重试按钮，
因为实测 Chromium 会缓存同 URL 模块下载失败，解除网络故障后重新 import
并不会可靠重新请求。这只涉及模块加载失败，不改变设置内部 API 的局部重试。

`tests/ui/lazy-settings.spec.ts` 明确为组件 harness，不是桌面性能结论。
对应桌面刷新与首次设置入口已由上述 Electron 测试覆盖。
最终构建 48 项组件回归通过，覆盖设置深浅 / 窄宽屏、加载中取消、模块失败
隔离、帮助、原生控制意图、播放器控制栏交互；对应真实桌面再次通过证据为
`build/electron-external-removal-f3n0vq/acceptance.json`。
设置代码单独分块约 55.34 kB，首页入口脚本约 448.89 kB（压缩前）；不是
把代码体积减少等同于确定的冷启动延时改善。共享样式没有为缩包而延后。
新增外部移除桌面回归和按需加载组件测试已接入 CI，本轮没有运行云端任务。
启动 trace / 权限策略通过；退出策略及 6 种实际桌面关闭 / 重启情形通过。

流畅度；窗口释放 2–67 ms，完整关闭最长约 6.57 秒。

## 尚未关闭的边界

偶发重启超时没有稳定复现。退出 harness 已增加失败 DOM、页面错误、API
响应和资源时间线取证，保留原等待预算，不以放宽超时冒充修复。
有界合成样本并发验收不等于数小时真实 4K/HDR 验收，也不证明无内存泄漏。
