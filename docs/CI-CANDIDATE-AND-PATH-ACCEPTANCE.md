# 首次云端失败复现与候选验收门禁

2026-10-22；版本保持 0.2.15。本轮仅修改、构建及本地验证，不打包、推送、
移动正式标签或发布。冻结网页版归档未改，未访问或修改 E:\downloads。

## 失败证据

正式标签运行 39735236983、main 运行 39735237035 均在 Backend regression
失败：567 项中 9 项失败，后续打包和发布跳过。依赖准备、审计与 UI/Electron
构建均已通过，不是 EXE 上传故障。

8 项扫描相关失败共享测试夹具路径不一致：生产扫描器使用完整规范路径，
夹具却直接把短 TEMP 路径写入测试库；查询、快照键及路径相等断言出现差异。
另 1 项 SQLite 损坏缓存测试给准备脚本注入短形式 ROOT，安全检查比较规范后
下载目录和未规范的测试 ROOT，提前拒绝，未进入预期哈希检查。

修复前，在本地真实 8.3 TEMP 复测四个模块，共 46 项，稳定复现同样 9 项失败。
不是根据日志推测后直接重跑。未将短 TEMP 改成长形式以绕过复现条件。

## 修复与防回退

- ScanJobsTests 夹具根目录在生成后 resolve，与真实扫描器持久化表示一致。
  测试媒体仍只是隔离的生成占位文件，保留原有事务、修订号、唯一记录、回滚和
  源不变断言。另增加真实短路径输入与完整路径复用同一媒体 ID、不重复探测的测试。
- SQLite 测试注入的 ROOT 同样规范化；产品路径越界、损坏档案拒绝和不联网/
  不覆盖断言不变，没有降低生产安全检查。
- 新后端入口统一 verbose 日志与 JSON 结果，失败也保留测试名和堆栈；报告在
  build/backend-tests，CI 故障附件收集 .log/.json，不收集测试数据库或媒体。
- 短路径后端验收从精选扩到完整发现的测试集合。CI 必须获得真实 Windows 8.3
  别名，否则失败，不能将跳过标成通过；不修改系统 TEMP。
- scripts/verify-windows.py 从工作流读取源码验收命令，本地默认只列计划，
  --execute 才运行；不另维护测试清单，不包含安装、打包、标签与发布命令。
- 正式标签增加只读候选门禁：同仓库、同完整 SHA、成功的手动工作流、完整
  打包/EXE/ZIP/清单/附件步骤通过，且成品附件未过期。普通 main 成功、原生
  专项、其他提交、跳过打包、空/过期附件不能放行。API 不可用时保持关闭。
  使用模拟 API 的单元测试覆盖拒绝路径、正确放行和分页；不把模拟当作云端验证。

## 下一步与边界

本地通过不代表 GitHub Actions 已通过。需要用户授权普通源码推送及手动云端
候选构建后，先验证新提交；同一提交候选通过，再经授权处理尚未发布的正式标签。
版本沿用已准备的 0.2.15，不为重试另升补丁号，不覆盖已公开版本。

标签仍重新构建并验证自己的成品；门禁降低“首次完整云端验证就是正式发布”的
风险，不是保证网络、第三方下载或 runner 永远不失败，也不以自动重试系统写入
或放宽测试来提高通过率。具体操作见 GITHUB-ACTIONS.md。
