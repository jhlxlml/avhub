# 项目私有 SQLite 运行库接入

延续 [升级评估](SAVE-PRIORITY-AND-SQLITE-UPGRADE-ASSESSMENT.md)。本轮应用版本不变，
只更新开发后端和未来 CI/打包配置，没有打包、推送、发布或迁移用户日常媒体库。
全部变更数据库的验收使用自建隔离样本，未操作 `E:\downloads`。

## 固定来源与真实加载

采用官方 Windows x64 SQLite **3.54.1**，保留 CPython 3.13.11 与标准库 sqlite3 API：

- 官方来源与预编译包校验：[SQLite 下载页](https://sqlite.org/download.html)。
- 版本与源码标识：[3.54.1 发布说明](https://sqlite.org/releaselog/3_54_1.html)。
- 固定下载 `https://sqlite.org/2026/sqlite-dll-win-x64-3540100.zip`，不是动态 latest。
- 压缩包 SHA3-256：`c2d09c8babb9399277055c057c97a53f1ffd7c5f11d0c1f2118ffdfa39f2daa4`。
- DLL SHA-256：`4b59d3cded9dc1608544160f3b4b10ac974c6ac0d6ffc23064e5f4c8dbd05aea`。
- 实际源码标识：`2026-10-16 14:45:20 555e07ef33f69a0957d24d8e555b702464a131d6f1607f4c3c1e4551e8e6ca76`。
- DLL 3519488 字节，位于项目 `bin/sqlite/3.54.1/sqlite3.dll`，不进入 Git。
  清单 `app/sqlite-runtime.json`、来源/公有领域说明保留在源码中。

`run.py` 在 uvicorn、应用、迁移和任何库访问前初始化。绝对路径加载，不改全局
PATH、系统 Python DLL 或 Windows 目录；校验 PE x64、哈希、实际加载路径、SQL
返回版本/source ID、线程模式和关键默认值。进程只持有一个已核对的 SQLite。
若旧 DLL 已先被其他模块加载，明确拒绝冒充新引擎；不卸载正在使用的引擎。

准备阶段允许显式联网，但启动时不联网、不下载、不回退。校验失败在创建应用
数据库前终止。准备脚本不覆盖不同的已有 DLL，不解压任意 ZIP 路径，限制下载
容量并验证固定包、成员列表、文件长度及 DLL 哈希；临时文件仅在自身目录清理。
同一用户若能任意修改应用源码与 manifest，属于应用安装目录本身的信任边界，
哈希校验不等于给未签名软件提供代码签名或管理员级防篡改保证。

## 接入入口与使用

```powershell
npm run prepare:sqlite
npm run check:sqlite
npm run dev
npm run test:backend
```

准备一次后日常使用离线。不要将该 DLL 复制到系统 Python、系统目录或媒体目录。
不同的已有文件不会被自动覆盖；若损坏，应先核对/保留该项目专用文件，再按
明确目标修复，不删除 `AVHub-data` 或系统 DLL。

专项 Python 脚本使用同样的加载入口：

```powershell
python scripts/python-runtime.py -m unittest discover -s tests -p test_sqlite_runtime.py -v
python scripts/python-runtime.py scripts/benchmark-sqlite-checkpoints.py --writes 1000
```

直接运行系统 Python 的脚本仍可能使用宿主 SQLite，不能将其测试结果声称为本轮
桌面引擎验收。`npm run test:backend`、渲染器隔离服务及 Electron 管理的 run.py
已接入新引擎。诊断导出记录实际 SQLite、source ID、线程/编译信息和校验状态；
普通直接模块 harness 会明确报告 `host-module-harness` / verified=false。

在本机重新独立执行系统 Python，仍报告 SQLite **3.50.4**，证明没有改系统运行库。
构建指纹也覆盖 SQLite manifest，避免只改依赖清单却仍声称同一个后端构建。

## 持久化和兼容性

不改 schema、保存 API、FULL 持久化、默认 1000 页自动检查点、串行写入与有界
保存优先队列；不新增并行 checkpoint，不改视频解码器、封装、画质或转码权限。

宿主与私有引擎实测关键默认值相同：synchronous=2、wal_autocheckpoint=1000、
foreign_keys=0、recursive_triggers=0、page_size=4096、cache_size=-2000、
auto_vacuum=0、temp_store=0。编译器和可选编译选项并不完全相同；没有把两个
二进制说成只有版本字符串不同，也没有启用新增扩展来改写应用行为。

隔离子进程使用真实应用 schema，旧引擎生成媒体元数据、进度、收藏、标签及片单，
提交后故意退出并留存 WAL。新引擎恢复读取、更新进度、生成一致性备份；旧引擎
再次读取和写入新版备份，新引擎又从回退备份恢复。各阶段核对完整性、外键、
进度、收藏/标签/标题/片单、FULL/自动检查点和自建源文件不变。

这些是生成应用库的跨版本测试，不是“任意用户旧库都已验收”。首次将既有日常
库交给新运行库前，建议在旧版设置中保存完整备份；不要手工复制运行中的主库
并丢弃 WAL/SHM。当前工作没有打开、改写或备份用户日常库。

## CI 与未来打包防护

- 两条 Windows CI 准备固定私有运行库；后端和短路径测试从同一入口加载。
  没有触发 Actions，此处只表示本地配置已接入。
- 构建脚本显式传入固定 DLL、manifest、来源/公有领域说明及 PyInstaller 用户
  runtime hook。仅解析语法、做单测，本轮没有运行 PyInstaller 或构造发行包。
- 后端收集完成后必须核对只有一份 `_internal/sqlite3.dll`，哈希和 manifest
  与源码一致；若依赖分析误收集系统旧 DLL，停止后续 Electron 打包。
- 未来 EXE / ZIP 的成品启动测试要求实际后端报告固定版本和 verified=true。
  文件夹 ZIP 必须包含 DLL 与清单。这些门槛不代替将来的实际冻结运行验收。
- 不为了测试放宽包内用户数据、旧网页归档、媒体、路径穿越或发布权限限制。

升级主要是引擎维护与安全修复，不保证消除操作系统 I/O、当前事务长提交或视频
缓冲。性能结论必须来自真实 Electron 解码帧、保存/锁等待等观测，而非换了版本
或不显示加载提示。
