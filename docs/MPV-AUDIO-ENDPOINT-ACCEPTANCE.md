# 原生音频输出端点诊断与重试交接

验收日期：2026-10-19。构建：`616c08c29c7596d6`。
本轮未升版本、打包、推送或修改用户媒体；没有改变系统默认声音设备或音频服务。

## 结论与边界

此前的 4K 首次打开失败为结构化 `audio output initialization failed`，并非仅靠
界面提示推断的解码/硬盘瓶颈。本轮只读枚举中，MPV 在当前测试会话仅返回 `auto`
占位项，没有实际输出端点；提升权限后的两个 Windows 音频服务均运行中。
不能将受限环境中查询不到服务、或无法访问 CIM，解释为用户系统服务不存在。

随后用真实 Electron、实际 MPV 和项目生成的 640×360 H.264/AAC 文件复现同类
错误，两种窗口模式均如此，未注入故障。它说明此会话的阻碍并不只发生于 4K
视频，也支持“当前会话没有检测到可用声音端点”的针对性提示；不证明用户日常
交互桌面同样无端点，不确定是远程会话、设备连接、驱动还是其他系统条件所致。
历史成功日志中出现过远程音频输出，不能据此断言当前失败一定由远程桌面引起。

此轮修复的是故障诊断与恢复交互，不是通过软件制造一个不存在的音频端点，
也不声称实体有声播放、插拔后恢复或音频保真已经验收。

## 修改

1. 只有收到音频输出初始化失败后才观察 MPV 的 `audio-device-list`。
   健康起播不增加设备枚举预检、轮询、固定等待或源文件重载。
2. 区分“当前会话未检测到可用输出”“已检测到输出但初始化失败”和“未知”。
   仅导出可用状态及计数，设备 ID、名称、描述不进入播放快照或应用诊断。
3. 失败会话仍存活时，设备列表变化只更新提示。检测到端点后由用户点击同一
   “重试原生播放”，不自动重播或切换设备。若会话已清理，重试会创建新会话。
   从不存在的设备恢复到实体输出的成功路径仍待交互桌面验收。
4. 继续坚持原文件播放，没有加入 `ao=null`、关闭音轨、自动静音、音视频转码、
   降低分辨率、改色彩/位深或重启系统音频服务等绕过措施。
5. 真实失败重试中发现“返回媒体库”在会话交接期间可能表现为可用却不响应。
   重试忙碌与导航保护现在覆盖旧会话清理到新会话附着的整个交接阶段；按钮状态
   与保护一致。原生事件的长生命周期回调使用递增 ref 代次，避免连续重试读取
   旧 attempt、设置同一状态而无法再次启动。正常播放不增加等待。
6. 新增纯状态回归并接入现有 CI 的无运行库下载步骤。没有触发云端构建或发布。

设备属性行为参考 [MPV audio-device-list](https://mpv.io/manual/stable/#command-interface-audio-device-list)：
`auto` 是默认选择项，不是实体设备；设备列表可观察变化。应用不通过写入
`audio-device` 假装重新启用已失败的音频输出，而是显式重新创建会话。

## 验证

- 前端与 Electron 编译、`git diff --check` 通过。
- `native-audio.mjs`：缺失/错误设备元数据、去重计数、隐私过滤、失败后才订阅、

  React 按钮与原生事件重试、设备恢复提示不自动打开等覆盖。不是原生解码验收。

### 最终构建的真实 Electron 报告

- `build/native-audio-output-MMZ1Qy/acceptance.json`：无故障注入的含音轨样本。
  两模式均报告音频输出失败、0 个可用端点；手动重试产生新会话，但仍因同一
  环境条件失败；随后能够返回媒体库，正常关闭，样本哈希/修改时间不变。
  报告 `physicalAudioAccepted=false`，不将故障交互通过写成音频播放成功。
- `build/native-audio-recovery-YSu2xK/acceptance.json`：真实 Electron/MPV 进程，
  video-only 样本配合确定性结构化故障注入；两种模式从加载失败及已附着失败
  重试到新的实际解码进程，时钟继续，未降级引擎；样本不变、正常退出。
  此项验证错误恢复程序，不证明实体 WASAPI 恢复。
- `build/native-independent-kAbu72/acceptance.json`：独立窗口定位、截图、全屏、
  连播、保存失败恢复及退出通过。
- `build/native-app-flow-IabycS/acceptance.json`：内嵌入口定位、时钟继续、片尾
  连播及退出通过。后两项是隔离生成样本，不替代 4K/HDR/多屏合成验收。

新手动入口：

```powershell
npm run test:electron:mpv:audio
npm run test:electron:mpv:audio-output
```

第一个是确定性错误恢复回归；第二个是当前实际音频输出探测，结果按模式报告。
第二个探测即使 UI/分类检查通过，也必须查看报告的输出状态，不能将命令退出成功
等同于实体听音验收。它使用静音偏好避免测试音打扰，但保留所选音轨和真实输出
初始化；不是 `aid=no` 或 null 输出。所有样本、索引和报告均在 `build/` 下隔离。
