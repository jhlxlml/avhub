# 原文件供数隔离、手动诊断与无损交织对照

日期：2026-10-19。承接
[1080p 大 MP4 核查](CHROMIUM-DIRECT-PLAYBACK-INVESTIGATION.md)。
本轮面向现有 Chromium 播放器，不修改 MPV；不升版本、不打包、不推送。

## 已交付

### 原文件查询不再等待全局写锁

`/media/{id}/file` 由串行 `connection()` 改为既有 `read_connection()`。
只读 WAL 快照及媒体库恢复读门仍保留，不关闭恢复/文件安全保护。锁只影响
路径查询阶段，不把此次修复描述为此前整个视频一直持锁。

新回归确认写互斥锁被占用时仍能创建供数响应，恢复写门被占用时仍正确等待。
Range 语义、HEAD、If-Range、多区间、断连取消及关闭句柄均保留。新增 4 GiB
以上的逻辑偏移回归使用小样本/模拟稀疏读取，不分配几 GiB 的测试文件。

### 现有播放器手动诊断

播放页展开 **播放信息 → 采集并导出播放诊断（8 秒）**：

- 只在点击后采样，自动将视频移回视口；画面上有统一样式的取消提示。
  不重载源、不切换解码器、不改画质或倍速，也不常驻采样。
- 记录具体视频解码器、平台解码标记、GPU/驱动、分辨率、倍速、时钟推进、
  总帧/丢帧、帧呈现、缓冲与等待事件。暂停、跳播、变速或不可见时不把连续
  播放速率标成有效对照；切换源则终止此次采集。
- 原文件链路另统计采集中新增的范围请求、跨区间次数与接收字节。它们不是
  物理磁盘 I/O，不能包括采集前已经在途的全部数据；MSE 等路径标明范围限制。
- 只选择一个匹配/剩余的解码器候选；历史候选不明确时标为 ambiguous，不猜。
  已有调试连接会被保留，不强制关闭 DevTools 或分离别人的连接。
- 结束、取消、超时、离开时清除帧回调/监听器/临时状态，只分离本次拥有的
  调试连接。页面调用及 GPU 查询均有等待上限，卡住的页面不永久占用导出。
- 复用现有原生保存、临时文件写入/完成后替换、取消与文件夹定位流程。
  报告使用白名单，不导出视频标题、源路径/URL、音频设备 ID 或画面；不联网。
  普通“运行诊断”仍是独立功能，原有含路径的警告未删除。

中英文 README 已同步用法。真实主题切换后的深浅色局部截图均已检查；首次仅
设置 DOM 属性的浅色夹具被启动偏好覆盖，已改为点击应用主题控件并断言主题，
不将两张深色截图充作深浅色验收。

## 撤回无收益的读取实验

曾尝试每个请求从 32 KiB 起步、逐步恢复 1 MiB。原文件同一末段、相同基线
流程的 8 秒手动采集结果：

| 指标 | 原读取逻辑 | 递增读取实验 |
| --- | ---: | ---: |
| 新范围请求 | 167 | 177 |
| Chromium 接收字节 | 1,241,451,845 | 1,330,487,256 |
| 等待事件 | 0 | 0 |

原逻辑报告 `avhub-chromium-direct-BR2XuO`；实验报告
`avhub-chromium-direct-muQn4r`，均位于本机 TEMP。
实验没有减少供数放大，丢帧自身有波动，不能用实验末段零丢帧宣布优化成功。
**递增读取已完整撤回**，`media_delivery.py` 保留本轮之前的读取行为；没有
增加 sleep、限速或全局大缓存，不保留未经证明的性能参数。

## 无损交织短片段：有供数信号，未启用生产副本

只读从原片 6,500 秒附近生成约 35.16 秒的自有临时对照：
`-map 0 -c copy -map_metadata 0 -movflags +faststart`，实际 27,320,526 字节。
生成前要求至少 512 MiB 可用空间，输出上限 64 MiB、保留容量余量、进程超时；
只写新建隔离目录，不覆盖原片。保留该短片段及报告以便复核，不是产品缓存。

报告：`C:\Users\liu\AppData\Local\Temp\avhub-chromium-direct-xZt45v\performance.json`。
同样两个稳定采样阶段及一次手动采集均为原文件直放、单次附加源、正常退出，
原片大小/修改时间一致，视频仍 1920×1080 H.264 yuv420p、音频 AAC。

| 对照 | 整个诊断的范围请求 | 两个稳定阶段丢帧/总帧 |
| --- | ---: | --- |
| 大原文件 | 1,126 | 34/453、39/456 |
| 35 秒交织短片段 | 4 | 15/456、10/456 |

另对源片对应约 45 秒窗口与对照文件的编码数据包做 SHA-256 多重集核对：
**2,853 个对照包均能在源片窗口的 3,408 个包中按轨道/哈希/数量匹配**，含
音视频两轨。不是仅根据文件分辨率或画面主观判断无损。

短片段能完整预读，手动采集阶段没有新请求不代表没有读过文件；长度、预读
状态和定位时间戳均与整片不同。该对照支持“交织布局可减少这类请求往返”的
方向，但不证明整部影片也按同一比例提速，不证明零丢帧/完整色彩显示或物理
声音同步，也不把 169 ms 的热缓存短片段生成时间当成整片冷盘准备时间。

**没有启用自动完整副本，也没有更改默认原文件直放。** 本轮未实现生产分区
预读缓存；没有足够真实收益证据前，不先加入复杂缓存生命周期或默认占用几
GiB。后续可优先复用已有有界按需无损封装，而不是强制复制所有 MP4。

## 回归与边界

- 10 项传输/取消/大偏移及 2 项数据库并发回归通过。
- 4 项手动导出/取消/离开/错误/深浅色 renderer 夹具及 7 项既有跳播反馈夹具
  通过。夹具不冒充桌面验收；其中一次服务器退出有 WinError 10054 连接重置
  日志，11 项断言仍通过，未把该日志解释为播放失败。
- 诊断纯契约覆盖脱敏、候选歧义、已有调试器、暂停、取消、切换源和无响应
  页面超时；真实 Electron 页面导出另行通过。
- 前端/Electron 编译及 `git diff --check` 通过；相关契约/组件加入 CI 配置，
  本轮未触发 GitHub Actions，也没有声称整个历史测试集都通过。

最优先的下一步是在问题电脑上用同一问题视频导出手动诊断，区分软件解码、
平台解码但帧呈现异常、等待供数及范围请求放大。然后针对证实的异常 MP4
评估显式、有界、可取消的无损按需交织方案，并补普通 MP4/高码率 4K 回归；
不以降低质量或隐藏等待提示代替修复。
