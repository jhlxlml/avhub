# 备份、查询竞态与分批清理验收

## 范围

本轮按审计建议推进备份生命周期、收藏查询竞态、清理批次与顶栏样式收敛。
未升级版本、打包、推送或发布；冻结网页归档和原视频未修改。
最终开发构建：`0.2.16 / 28c2cca25ce37989`。

## 实现

### 备份与恢复

- 数据库一致快照仍保留写锁及恢复排他保护；校验、复制封面和 ZIP 打包不再
  长时间占用写锁。每次仅打开一个图片句柄，随后在锁外复制到私有暂存，
  从同一私有副本计算哈希及打包，避免重新打开可变缓存造成校验不一致。
- 在快照锁内固定手动封面引用，保护被同时编辑退休的旧封面；结束后解除
  保护并重新核对引用。自动封面在捕获时核对源路径、大小、修改时间和引用，
  不再匹配的自动封面不纳入备份。无损视频播放链路没有变化。
- 外层快照持有恢复读门；内部图片打开和收尾不重复进入该门，避免等待恢复
  写者时发生嵌套读门死锁。新增了明确持有等待写者的回归。
- 新数据任务持久化所属 PID、任务 ID、类型和阶段；恢复提交前落盘标记。
  只回收归属可确认、进程已退出、目录内容均受支持且无链接的普通任务。
  活跃任务、提交中/失败待核查任务、未知目录和无标记历史目录保留。
- 失败的恢复暂存不会被取消、超时清扫或退出收尾误删；界面可以与其脱离，
  继续备份，但不会删除证据。恢复任务回收统计进入本地诊断。
- 任务暂存预留上限为单任务 7 GiB、任务总量 8 GiB，至少保留 128 MiB 空间；
  完整备份包仍限 2 GiB，恢复数据库校验限 512 MiB。预留量是保守预算，不代表实际占用。
  上传、解压、封面捕获、归档均检查预算；恢复在修改前额外预留回滚数据库、
  新手动封面和旧缩略图暂存的峰值空间。空间不足不能先改库再报错。

### 收藏及查询

- 收藏回调绑定发起时的查询身份，不拿旧页面的收藏筛选条件更新新页面。
- 页面缓存增加写入失效代次；读请求若跨越已提交写入，则重新获取写后快照，
  不能把写前的旧结果覆盖到界面。同一查询重试保留现有数据，不整页闪烁。
- 覆盖延迟收藏后切页、写前 GET 延迟返回、失败保留状态、同页封面和悬停预览
  不被卸载的场景。

### 清理与样式

- 普通清理每批最多 64 个文件、约 25 ms 协作式时间片；批次间释放播放控制、
  数据库及封面发布保护。单次请求的删除工作约 2 秒后返回部分进度，剩余项
  需要核对新预览再确认，不在后台无限续删。
- 首批保留完整预览令牌与引用验证；后续批次核对本批源路径、缩略图/排队引用、
  回滚快照、活动播放缓存和逐文件身份。引用改变或任务启动时停止，已完成的
  数量及停止原因如实显示；不回滚已删除缓存，不删除原视频。
- 这是协作式预算，不是磁盘系统调用的硬实时上限。预检遍历、单次慢磁盘
  操作和首次引用验证仍可能超出时间片。
- 顶栏控件的 32 px 高度、18 px 图标与 6 px 间距归入共享设计令牌，移除
  Mira 中重复尺寸覆盖，保留响应式布局。只是样式收敛第一批，不宣称全项目
  所有历史 CSS 已完成合并，也没有重新设计播放器。

## 后续边界

无标记的历史暂存和未知文件不自动清除；失败恢复的暂存需要结合诊断核查。
后续优先扩大真实大库与播放/扫描并发的长时间验收，观察多轮返回/空闲后的
内存趋势，再逐模块收敛设置、片单等历史样式。偶发启动超时与耐久提交长尾
保留跟踪，不因本轮回归通过而宣布解决。
