## 已确认问题与处理边界

此前真实 Electron 注入只读 /api/file-operations/preview 不响应，6 秒后
请求仍未结束；点击关闭仅显示“文件操作正在进行”。没有执行任何文件写操作。
原因是主进程共用 fileActionBusy 且预检 fetch/JSON 正文均没有应用级期限。

本轮将 preview、preview-records 及两类预览缓存释放列为可取消请求：

- 10 秒覆盖响应头和正文读取，传入 AbortSignal，并以有清理的 race 保证异常
  传输忽略信号时仍结束 UI 等待。不自动重试；成功或失败都清理定时器与监听。
- 取消只匹配 32 位十六进制请求 ID。新窗口/新预检使用不同 ID，旧取消不能
  取消新预检，更不能取消写操作。IPC 仍校验可信主窗口、来源与输入。
- 批量回收预检可关闭，回收记录预检可取消或关闭；取消后项目未执行，不弹
  危险确认、不执行恢复/永久删除。卸载时移除监听并取消所属请求。
- 应用退出可取消只读预检，并继续原有保存/退出握手，不再将预检误认为
  已经开始的系统写操作。实际写操作仍阻止退出并保留结果确认。
- 重命名、系统回收、恢复、永久删除、权限写入和结果确认不使用这个超时包装，
  没有超时后重放、永久删除兜底、强制结束用户进程或放松目录权限。

取消的是客户端等待/传输，不承诺中止后端已经开始的只读 NTFS/系统回收站
枚举。后端预览缓存仍按既有限额/有效期管理；取消不是系统文件操作撤销。
这也不是宣称所有真正文件写操作异常均可直接强退，结果不确定仍须核对。

## 构建身份

Node 构建器与 Python 开发服务指纹同时加入 package-lock.json、requirements.txt
及 frontend/public 下所有原始文件。依赖锁、运行依赖、原始资源内容变化以及
资源新增/删除都改变 build_id；生成的 app/static 仍排除，避免循环指纹。
冻结后端仍读取内置构建元数据，不在用户电脑读取源码或下载依赖。

扩展既有隔离测试，每次都比较两端结果相同；确认嵌套 UI 变化改变身份、
生成静态输出变化不改变身份，锁/依赖/模拟字体/原始图像变化改变身份。
应用版本号和 API 协议未修改。
