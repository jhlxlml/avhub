# 播放架构改造基准与未验收项

命令：`node electron/test/playback-refactor-benchmark.mjs m0`，之后 M1 使用 `m1` / `m1-legacy`。
脚本固定复用 `build/playback-refactor-fixtures/media/` 的三个生成源，保存摘要、构建、GPU、
显示器与全部目标/实际帧时间；不访问、上传私人媒体。原片始终只读，MKV/TS 由同一生成
H.264 视频 stream-copy 而来。Remux 项显式请求无损封装，不能根据 MKV 后缀推断实际链路。

方法：正常 GPU/安全设置的真实 Electron，640×360 / 25 fps / SDR H.264，24 秒视频。
每格式两次起播、20 次固定随机暂停跳播。跳播耗时从进度条提交到 `requestVideoFrameCallback`
给出目标附近的新解码帧，目标允许误差 0.55 秒（报告保留实际误差）；不是媒体时间赋值或
loading 消失，也不是物理显示器扫描延迟。相邻近似同位置目标避免无操作采样。
第一/重开会话不等于清空操作系统文件缓存，不对 OS 冷缓存作保证。
