## 连续样本与无损验证

新增固定生成样本 `Precision-SDR10-Continuous-3840x2160.mkv`：
将原 6 秒 4K25 HEVC SDR10 精度片段仅以 `-c:v copy` 连成 180 秒时间轴，
由一个文件顺序播放，mpv `loop-file=no`，内容仍重复，不是 180 秒独特运动场景。
不改编码、尺寸、位深、色彩或视频包；没有接触 `E:\downloads`。

- 150 个原视频包对应输出 4,500 包，逐包 SHA-256 与原片段的对应包相等。
- 对照原 PTS 加周期偏移验证时间轴，检查已知 DTS 严格递增；B 帧开头缺失 DTS 不被假设为零。
- 正常创建时在发布缓存前校验，复用缓存仍重验。生成锁、排他临时文件、安全发布及超时继续保留。
- 文件 122,735,821 字节，保持单文件 128 MiB、总样本 512 MiB 与生成前剩余空间检查，未扩大缓存额度。
- 第一次生成因沙箱硬链接权限失败，完整权限重试后又暴露 DTS 首值缺失的检查错误；
  修正为 PTS 与已知 DTS 检查，没有删除数据哈希断言。

## 修正资源判定的方向

连续基线 `evidence-iriPfF` 原脚本仍为 **FAIL**：
晚期原生 GPU 占用范围约 191.38 MiB，超过绝对范围 64 MiB。
但最大值没有超过排空后的初始基线，变化是内存释放，并非正向增长。
该失败报告和上轮 900 秒句柄范围失败均保留，未改写为通过。

新增 `resource-convergence.cjs`，分别保留：

1. 全部原始最大值、最小值和绝对波动范围，供旧判定审计。
2. 相对播放前暂停且 GPU 引用释放后的中位基线，计算活跃峰值正向增长。
3. 播放后暂停、排空引用的 15 次采样，计算中位残留和空闲范围。

新判定沿用原生内存 64 MiB、句柄峰值 16 个的数值上限，另要求空闲句柄增长和范围各不超过 8。
**判定的语义已经修正，不能将新判定通过说成旧测试原样通过。**
旧绝对范围结论单独记录为 `legacyRangeWouldPass`，原失败结果不回填。
缺少 15 次排空样本、缺少指标或仍有 GPU 读者时不能认证收敛；不强制 GC。
3 个边界单测覆盖释放、持续泄漏和证据缺失，并加入 CI。

这次修正针对原生宿主资源，不代表已经设定或通过 Electron GPU 进程的长期内存门槛。

## 单项实现优化

SDR F16 WebGPU presenter 初始化时缓存一次 `getBindGroupLayout(0)`，避免每帧重复取得布局。
每帧仍为实际 VideoFrame 导入外部纹理并绑定；GPU 完成等待、精度与释放顺序不变。
没有取消绘制、降低质量或使用前一帧冒充新画面。
这消除了重复调用，但当前数据**不足以证明 GPU 内存泄漏被修复或端到端播放更快**。

## 两分钟连续播放结果

两次顺序运行，同一个生成片源、真实 Electron，当前 RTX4090 / NVDEC / SDR 显示；
报告位于 `build/libmpv-render-spike/`。每次 55 次实际像素采样。
不是长期 A/B 认证，进程缓存与系统波动没有完全控制，不能将数值差全归因于布局缓存。

| 项目 | 未缓存布局基线 `evidence-iriPfF` | 缓存布局 `evidence-pikqyn` |
|---|---:|---:|
| 实际播放 ms | 120,065 | 120,064 |
| 像素源时间 / 墙钟 | 0.999960 | 1.000020 |
| decoder drop 观察增量 | 0 | 0 |
| VO drop 观察增量 | 0 | **2** |
| 句柄排空基线 / 结束中位数 | 700 / 707 | 701 / 706 |
| 活跃句柄峰值正向增长 | 13 | 15 |
| 结束空闲句柄范围 | 3 | 2 |
| 原生 GPU 峰值正向增长 | 0 | 0 |
| 原生私有内存峰值增长 | 约 4.05 MiB | 约 3.58 MiB |
| 原报告结果 | FAIL：旧 GPU 绝对范围 | PASS；`legacyRangeWouldPass=true` |

两次连续播放中 VO 属性均无回落；复测的 2 次 VO drop 不能省略，也不足以认定布局缓存产生持续回归。
需要更长复测，不能据此声称“零丢帧”或已达到正式播放门槛。
同片连续时间轴比例接近 1，而上轮 6 秒循环约 0.948，支持循环重新定位影响测量的判断；
因时长及环境未完全匹配，不是严格因果或性能提升证明。

Electron 合计私有内存的晚期范围两次仍约 121 / 118 MiB；
该变化不构成显著优化证据，GPU 进程早期抬升的根因尚未查明。
本轮没有用新样本重跑 15 分钟，所以旧 900 秒失败仍不能标为已修复。
