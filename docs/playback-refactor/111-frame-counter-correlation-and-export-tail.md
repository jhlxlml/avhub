2026-11-11，延续 110。保留已有工作区改动和用户文件。修改范围仅为 `electron/test/render-frame-cadence.mjs` 与验收文档，应用源码构建仍是 `caf853a30ff23509`，没有新增生产播放调度修改、打包、版本升级或远程操作。

## 确认的诊断问题及修复

1. 页面与主进程的 `performance.now()` 起点不同。关联原生计数和 GPU 时间线时，改为在已有 snapshot RPC 返回时记录原生计数和主进程时间；不增加查询频率。以相邻查询覆盖区间表达计数增长，不伪造精确丢帧时刻或因果关系。
2. 旧流程在继续播放时先跨进程传输完整时间线，再读取页面计数和结束状态。数万条记录的序列化会阻塞 Electron 主进程，**导出本身能够造成新的输出丢帧**，而且后读的页面状态把这个尾部算入了稳态测量。
3. 新流程结束时冻结主进程记录，先保存播放中的结束状态，然后显式暂停、确认暂停成功，再导出大数组。断言导出后记录数仍与冻结时一致。计数汇总只用冻结前已有的原生 snapshot，页面事件仅供 UI 状态排查，不跨时钟关联。
4. 支持单个 300 秒窗口；记录上限为 120000，页面事件上限 4096，均检查没有截断。最长交付间隔先选前 16 个再展开相关调用，避免对长窗口的所有间隔逐一全表扫描。

这些是测试工具修复，不代表普通应用的诊断复制功能有同样的大数组问题，也不代表用户感受到的所有等待已解决。
