# MPV 跳播设置与开发启动统一

本轮基于尚未提交的 MPV 跳播优化继续实施，版本保持 0.2.19。原始媒体及历史网页归档未修改。

## 用户操作

媒体库设置 → 播放偏好 → 默认跳播模式。选择精确、快速（关键帧）或智能，写入 SQLite，全局生效于之后打开的视频。当前视频的临时切换不覆盖该默认值。

内嵌播放页和独立窗口状态页增加「跳播与播放设置」文字入口。内嵌入口打开原有设置面板，独立窗口入口唤出其原生设置面板。原生控制栏的滑杆按钮仍可使用。播放页保留实际关键帧偏差说明。

## 智能模式

修复原来需要先手动切换快速模式积累记录的缺口。同一打开源的播放中远跳（至少 10 秒）完成三次精确测量后，平均耗时达到 150 ms，下一次合条件的用户跳播可尝试关键帧。没有额外后台跳播。

首次关键帧结果即可参与决策。保留每种策略最近四条记录，关键帧平均至少节省 30 ms、耗时不超过精确的三分之二、已观察偏差均不超过 2 秒时才继续。结果较慢或偏差大则回到精确。暂停和短跳精确定位。2 秒是已观察结果的决策门槛，不能预先保证下一个 GOP 的偏差。

阈值是基于现有配对结果采用的保守实现选择，后续可根据实际使用修订。关键帧不会降低原画质量。

## 开发启动

npm run dev 继续通过 Electron 启动。构建前端和主进程后，scripts/start-electron-dev.mjs 校验原生宿主与源码哈希，必要时重新编译。已具备固定发行同系构建材料时，优先复用已校验的 replayed 运行库。原生源码变化时调用既有 staging 流程生成对应运行库，普通重启复用现有目录。

显式 AVHUB_RENDER_RUNTIME_CANDIDATE 优先；验证失败直接报告，不跳过哈希检查。尚未具备发行同系材料时可使用现有开发运行库，其身份在启动输出和播放偏好中显示。依赖缺失仍可打开应用使用其他可用引擎。脚本不下载依赖，不生成应用发行包。
