# 原生播放交互与设置精修

2026-11-13。基于 `cc23cc5` / 0.2.21 进行本地增量修整；未升版本、未打包、未提交或推送。保留用户的 AGENTS.md 修改与根目录架构方案。

## 实际修改

1. `RenderPlayer` 将截图的画面读取/编码保护与 PNG 发布分开。画面保存到临时 PNG 后即可继续暂停、播放、跳播和音量操作，不再因为目标文件仍在保存而拒绝全部控制。读取期间的操作等待真实帧完成；截图失败也释放等待。重复截图与关闭仍等待完整任务，不提前报告成功。
2. 内嵌播放诊断从 MPV 已选择的视频轨道提供编码（排除封面轨道）；分别显示命令到确认与包含排队的总耗时。没有采集的音视频就绪、完整缓存累计不冒充读数，界面说明该路径的测量边界。未改动原生宿主、呈现事件或解码策略。
3. 设置将独立窗口、D3D11 内嵌、窗口叠层放进同一显示方式选择器。切换通过一次偏好 PATCH 保存；D3D11 保留旧窗口偏好，切回窗口路径同时关闭 D3D11，失败时恢复显示。实验控制开关收进默认收起的高级选项，使用共享开关样式；移除运行库提示中的“验收”术语。默认引擎、既有偏好、原画路径保持。
4. D3D11 内嵌控制栏使用实际队列边界禁用上一条/下一条，随机播放依据完整可播放数量判断，切换时禁止重复输入；快捷键遵循同一可用状态。独立 MPV 的 Lua 控制栏和历史窗口叠层导航未扩展新的 IPC 协议。

## 初次失败与限制

- 首次确定性测试的 Electron mock 未提供 `app.isPackaged`，修正 mock 后 PASS，不作为播放修复。
- 源码回归首次在受限文件系统下执行，媒体池硬链接/符号链接合同报 EPERM；在正常 Windows 测试权限下完整重跑，16 步 PASS，未跳过断言。
- 初次设置桌面测试在增量 CSS 改动尚未重新构建时出现 startup-error/等待入口超时（`render-settings-status-P87dz2`）；未将其计为 PASS。重新构建后同一测试通过。原报告未捕获完整页面错误，不能以此证明一般性启动问题的根因。
- `mpv-window-coexistence.mjs` 的一次调用因未提供它要求的成品 EXE 而拒绝执行；本轮只授权源码迭代，不重新打包，也不以旧成品代替新源码。实际跨路径开发构建验收使用 `playback-path-cycle.mjs`，上述成品测试保持未验收。
- 不宣称本轮通过新成品、外机、物理 HDR 色彩或多屏 DPI 验收；没有原生吞吐提升的额外结论。截图读取/编码本身仍需真实完成，这次主要解决文件发布阶段阻塞操作的问题。
