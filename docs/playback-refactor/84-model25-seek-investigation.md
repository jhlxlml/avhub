## 没有推广无收益参数

直接 nvdec 在当前 D3D11 输出不兼容。mpv-seek-paired-DDOZE2 FAIL / 1，实际 hwdec=no，被测试明确拒绝，未算作有效硬解优化；日志原文为 CUDA hwdec only works with OpenGL or Vulkan backends。

nvdec-copy 保持硬解，但精确差异仅约 2%–3%，尚不足以推广替换，且引入 GPU/CPU 拷贝。单线程更慢。没有关闭硬件加速、减少原始位深/分辨率、静默转码、跳过画面确认或把关键帧偏差伪装为精确成功。

本轮没有可证实显著有效的精确定位提速，因此生产参数与默认精确模式保持。快速模式仍是已有显式选项，只改变落点精度，原画质不变；智能模式保留已有精度保护。

## 测试工具修复

首轮 readFileSync 计算大于 2 GiB 文件哈希失败 / 1，是测试工具上限，不是播放器读取上限。测试改为 createReadStream + pipeline 流式 SHA256，避免把 3.6GB 文件一次性放入内存；每轮前后核对原文件与副本 SHA256。复制前校验剩余空间，保留至少 1 GiB 余量。

配对脚本增加受限的硬解后端、线程、后段目标参数，均仅对隔离试验 MPV 注入，不进入应用设置。真实样本 override 限制于已授权 E:/downloads。读写验证仅操作应用拥有的 build 副本与日志。

本轮是确证瓶颈与排除负优化，不声称已修复该视频精确跳播的解码等待。要获得几十毫秒响应可显式使用快速定位并接受约一个 GOP 内的时间偏差；精确模式继续保持实际落点与画质。现有开发数据目录只读查询未保存 mpvSeekPolicy，对应默认 exact；没有替用户改偏好。该查询不能代表其他便携数据目录或播放页临时选择。


## 后续线程与设备核验
