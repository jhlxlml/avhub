# 损坏着色器缓存恢复与起播回归

2026-11-09；版本保持 0.2.19，产品构建 872cc8bd67b29a88。原生源码/宿主未再更改，继续使用匹配的 `render-replayed-candidate-KhYHON`。保留其他未提交修改、原规划文件与旧报告，不提交、不推送、不打包。

## 真实问题

上轮验证了未知缓存目录的回退，但没有覆盖编译二进制本身的损坏。本轮在实际 Electron 的隔离数据目录先正常播放/关闭，再破坏五个已生成 shader 的 DXBC 校验字节。视频源完全不改动。

修复前 `build/render-app-flow-1zSIZS/report.json`：FAIL / 1。重开后请求帧码 31，实际 compositor 图像持续为帧码 0。MPV 的程序头版本检查不能代替编译二进制内容完整性，也不能把存在 GPU 完成回执当作画面必然正确。不是通过隐藏加载提示解决的问题。

## 修复

- 自有 shader 缓存增加 `.avhub-integrity.json`，记录编译文件名与实际 SHA256；仅由可信主进程维护，不接受 renderer 指定文件路径。
- 在宿主已完全退出后记录本次有效缓存；下一次打开前逐文件核对。内容变化、未记录或旧缓存缺少索引时，丢弃相应**自有编译缓存**并由原生引擎重新编译。不改变视频、渲染算法、分辨率、位深、色彩或硬解策略。
- 索引损坏/不完整时不接受未验证程序。索引限定 schema、项目数量、文件名及 SHA256 格式，并设读取大小上限。读文件每批最多四项，单项沿用 4 MiB 上限。
- 沿用上轮 owner 标记、目录联接/未知对象拒绝及闲置容量回收。只在实际启用了这份缓存的会话退出后记录完整性，未启用的目录不擅自接管。
- 这是防止缓存意外损坏的本地记录，不是数字签名或防本地恶意用户篡改的安全认证。
- 老版自有缓存首次使用时可能重建一次；观看记录、字幕、偏好及所有源视频不受影响。源 shader/参数变化仍由 libmpv 的内容哈希键和程序头处理。
