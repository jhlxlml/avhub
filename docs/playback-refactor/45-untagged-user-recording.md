# 未标定色彩录屏：拒绝原因与现有播放路径

用户提供项目根目录的「屏幕录制 2026-10-29 090659.mp4」。只读检查；样本由现有媒体忽略规则排除，未加入发行包或版本库。测试只索引自有隔离副本。

## 实际原因

FFprobe 容器／前 32 包解码帧证据保存在 build/recording-20261029-probe.json。H.264、2510×1302、30 fps、yuv420p、方形像素，时长约 28.31 秒。容器和首个视频解码帧均未提供 color_primaries、color_transfer、color_space、color_range。

当前 D3D11 单屏 SDR 准入要求经验证的 BT.709 色彩与明确范围，因此在启动原生宿主前拒绝此样本。这个现象既不证明新电脑 DLL 加载失败，也不证明 MPV 解码该文件失败；尚未执行那些阶段。缺少标记也不能直接证明源为 BT.709 或 HDR。

没有修改准入范围，没有写回或补写源标签，没有转码、降位深、降分辨率或自动切换引擎。若后续扩大到未标定文件，需另行验证 libmpv 自动色彩解释与显示路径，不能将未知标签直接替换为已验证 BT.709 合同。

## 改进

app/native_playback.py 对未标定色彩明确列出缺失字段，提示用户主动切换现有播放器。其他首帧、冲突、探测、尺寸、像素比例及旋转检查保留，并分别提供可理解的原因。只展示受控原因，不将任意探测输出或文件路径直接放入错误提示。

tests/test_native_render_source.py 补充真实样本形态的未标定元数据、输入不变以及探测／旋转原因测试。相关后端测试共 12 项通过。
