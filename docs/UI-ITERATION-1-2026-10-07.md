## 已完成

| 范围 | 结果 |
| --- | --- |
| 桌面导出 | 备份、诊断使用原生保存窗口；成功落盘后显示路径、大小和定位入口；取消 / 失败有明确反馈 |

| 暂存回收 | 导出读取结束后请求释放后台备份暂存；活动读者由后端 pin 保护。连续导出超过 8 次不会占满数据任务池 |

| 计数与空状态 | 剧集分组以“部剧集”计数，单集以“集”计数；无目录、未建立索引、扫描中、空分类、筛选无结果和选中目录离线有对应文案与动作 |
| 目录管理 | 添加目录后可立即扫描该目录；移除前展示路径、当前可浏览视频数量及库内影响，说明原视频不删除 |
| 文档与 CI | 中英文 README 同步使用入口；新增真实 Electron 工作流脚本并纳入普通 Windows CI，未触发新的云端运行 |

## 验证

- TypeScript、Vite 与 Electron 编译成功，`git diff --check` 通过。
- 59 个不同相关共享渲染器用例分批通过，覆盖媒体库、完整备份恢复、数据任务、诊断、截图、设置、菜单、续播、播放器状态与两种主题。并非在一次运行或同一个中间构建上完成的全项目测试。
- 首轮回归发现旧用例仍期待 7 类存储、旧的菜单首项、已退役的浏览器原生操作路由，以及早期按键 / 鼠标唤出控件规则。用例改为当前已有的 8 类存储和 preload 接口，并保留数量、焦点、媒体 ID、确认、快捷键保护与真实时间断言。
- 浏览器备份 / 诊断用例使用明确标记的 `native-export-harness.ts`，仅模拟原生桥接并验证组件与后端内容。生产源码没有浏览器导出回退；桌面验收使用真实 Electron。
- 最终构建运行 `electron/test/library-workflows.mjs` 成功：实际索引合成视频、独立编辑 / 保存、放弃关闭、截图草稿跨标签保留、全部条件清除、剧集计数、原生 IPC 导出、连续 9 次额外导出、取消、错误目标、诊断保存、目录移除取消和参数拒绝。
- 导出取消 / 截断传输还在真实 Electron 主进程中使用受控流检查：原有目标内容保留，没有遗留 `.partial`。此项为受控故障验证，不代表实际磁盘故障或超大文件性能实测。

- 合成源视频 SHA-256 与修改时间保持不变。没有读取或修改日常原视频。
- 检查真实窗口中的独立编辑深浅色截图，修正基础模态表单规则造成的横向挤压，标题 / 标签保持整行，其余字段为两列。

## 保留的边界

共享渲染器窄视口用例只验证组件布局；普通 Electron 窗口的最小尺寸、DPI、纯净窗口和原生对话框行为仍以桌面验收为准。本轮未重测真实 HEVC / HDR 解码、首帧 / 跳播性能、真实多 GB 导出或全量后端回归。既有 Vite 配置 / 分块警告和测试主动断连时的 Windows `10054` 日志未作为已解决项。
