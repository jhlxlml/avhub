## 回归中一并发现和修复

- HLS 清单在 FFmpeg 更新时可能产生“旧 Content-Length + 新正文”，导致播放流失败。清单改为一次读取的快照响应，分片仍使用原有文件传输。
- Windows 读取/安全软件句柄可能使首次缓存删除失败。仅针对验证过的任务缓存目录进行短暂重试，失败目录进入后续回收；不跟随指向缓存目录外的路径。
- 在首帧已就绪但 playing 事件尚未到达时关闭页面，最终进度可能没有保存。保存判断补充已就绪帧检查，仍禁止续播提示和准备中的流覆盖旧进度。
- 目录回归用例的延迟路由在解除拦截时偶发“Route already handled”。测试现在等待在途拦截结束再更换处理器，不掩盖应用错误。

## 本地服务保护

浏览器和 Electron 都校验本机 Host 与实际服务端口；写请求验证 Origin、Referer 与浏览器 Fetch Metadata。无浏览器来源元数据的本机 CLI 仍可使用；Electron 额外保留随机会话校验。

防嵌入策略通过 FastAPI 和 Vite 的响应头提供，不再把 frame-ancestors 放在无效的 meta 位置。Vite 仅重写固定本机开发页面的 Origin，其他来源保持原样并被后端拒绝。

Electron 同时设置权限检查和权限请求处理器，仅允许本应用主页面的全屏与复制路径写入，拒绝摄像头、麦克风、定位、通知、剪贴板读取等不需要的权限。[Electron 权限接口说明](https://www.electronjs.org/docs/latest/api/session#sessetpermissioncheckhandlerhandler)。
