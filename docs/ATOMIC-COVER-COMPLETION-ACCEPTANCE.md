后续扫描元数据与封面入队合并见
[下一轮验收](ATOMIC-SCAN-ENQUEUE-ACCEPTANCE.md)；以下保留本轮历史结果。

## 改动与可靠性边界

原来每次成功生成封面后，先提交 media.thumbnail / updated_at，再由工作者另开
事务删除 thumbnail_jobs 中的任务。同一个成功结果需要两次写入提交。

现在在原有 cover-publish 事务中完成两步：

1. 重新校验媒体 id/root/path/size/modified/missing/normal 状态，以及任务修订
   和 pending 状态；条件匹配才更新封面索引。
2. 删除同一 media_id + revision 的 pending 任务，必须恰好删除一行。
   删除失败或行数不符则抛错，封面元数据和任务删除一并回滚。

仅在连接上下文真正 commit 成功后，才返回不可变 CommittedThumbnail 回执。
它保留 success/error 两值接口，工作者识别已提交回执后不再调用 jobs.finish，
不是仅根据解码成功、缓存文件存在或 UI 没有提示就认定任务完成。

- 提交前检测取消，包含等待其他写入后刚获得写锁、以及即将提交两个时点。
  此时取消会保留待办，不假报成功。
- 已成功提交后再收到暂停/退出，以持久化结果为准，计入 published，不复活
  已完成任务。提交之后的新重试拥有新修订，不会被旧回执的第二次完成动作删除。
- 提交失败没有成功回执。工作者沿用原错误记录/重试流程，不删除未完成任务；
  若连错误状态也不能保存，任务仍留在库中，不能声称成功。
- 非 normal 媒体不会进入解码/封面发布，排除回收或待核对状态。
- 保持 FULL、默认自动检查点、独立 WAL 生命周期和保存优先门；不把多张封面
  合成一个巨型事务，不在解码时持有数据库写锁。

JPEG 仍先在应用自有缓存中以临时文件原子替换，然后进行数据库提交。**SQLite
事务原子性仅涵盖索引与任务两项，并不让缓存文件替换也获得跨文件事务回滚。**
若在数据库提交前中断，可能留下可重建 JPEG，任务仍可恢复处理；提交后中断，
索引与任务完成状态一起保留。未做真实断电测试，不宣称文件系统级全链路原子性。

没有改变 JPEG 生成参数、视频解码/封装/转码策略、色彩、位深或原文件内容。
没有新增表、索引、后台检查点线程或应用设置。

## 功能验证方式

新增 10 项原子提交专项测试，使用自建数据库与占位源文件，解码阶段为明确的 stub，
不是播放性能或真实媒体兼容性验收。覆盖：

- 单次成功写事务内恰好两项行变化，保留用户标题/进度/收藏/自定义封面和源文件。
- 删除异常、零行删除、commit 异常均回滚两项数据库状态，不返回成功回执。
- 工作者收到回执后不调用第二次 finish，重复提交同一修订不会重新发布。
- 等待写锁时取消保留任务；提交后退出仍计入成功；提交后的新重试修订不受影响。
- 删除任务后、commit 前取消也回滚两项状态，恢复后同一修订可重新处理并成功完成。
- 实际工作者提交失败时保留失败详情，published 不增加。

原有封面取消、恢复、离线、重试修订、恢复排他门、只读检查绕过写锁等专项
回归也继续执行。真实 Electron 性能测试使用真实 FFmpeg 与实际提交，不使用
上述 stub，也不注入成功回执或改动保存响应来制造收益。

## 计数与性能结论的口径

完整开发构建 `002e3b6915dbf157`，性能运行期间生产源码保持不变。
使用此前相同的 1200 实体生成视频 / 60 子目录、正常 GPU/sandbox/后台节流，
扫描期间原文件播放、暂停保存、搜索及返回，排空封面后再增量扫描。

验收脚本新增强制断言：cover-publish 行变化数等于 published × 2，cover-queue
行变化数只对应入队，不再包含成功任务的第二次完成删除。既核对提交调用次数，
也核对该保存的数据没有被省略。

降低的是成功完成一张封面所需的应用级 commit 调用：两次变为一次；加上入队，
整个封面流程由约三次变为两次。**不是整个应用的提交数或扫描耗时减半，也不是
物理 fsync 计数实测。**短时间正常保存不证明长尾已根治。

**最大提交与最大后台排队没有改善，反而高于这一次历史对照。**本轮最慢提交

  cover-publish 为 630 次 / 1260 项行变化，cover-queue 为 613 次 / 606 项行变化；

- completed / cleanExit / sourceUnchanged 均为 true，errors 为空，私有 SQLite
  verified=true，退出后 WAL 为 0 字节。

  操作最大 commit 为 8.75 ms、最大写锁等待约 0.10 ms。**长尾仍然存在**，

该轮仍是约三分钟的生成样本测试，虽采集内存，也不构成数小时稳定性、无内存
