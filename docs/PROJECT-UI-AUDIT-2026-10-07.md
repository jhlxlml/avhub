# AVHub 项目与 UI 梳理、下一步迭代建议

日期：2026-10-07。对象：当前 Electron 桌面源码，包含本次对话中已完成、尚未提交的分页底部布局调整。

## 结论

AVHub 已有较完整的离线媒体库与播放器能力。接下来的收益主要来自缩短常用流程、让操作结果明确可见、统一页面状态，以及完善真实桌面验收。现有密集封面墙、深浅主题、中文界面和原画优先方向适合继续保留。

建议下一轮首先完成 **桌面导出流程、独立媒体编辑入口、设置草稿保护、剧集计数语义和空结果反馈**。这些改动直接影响日常使用，能够独立验收，也不需要改变播放解码链路。

## 审查范围与证据边界

- 阅读当前前端页面、共享组件、样式、Electron 主进程与 IPC、后端模块、CI 配置和既有验收文档。
- 启动真实 Electron，在隔离档案中创建 8 个合成视频，实际扫描、生成封面、编辑测试记录、创建片单并播放。检查宽窗口与 800×620 窗口、深浅主题、主页面、设置、片单及播放器等 UI。
- 观察常规、空结果、长标题、后台任务、设置滚动与保存方式。设置截图目录的未保存草稿在切换标签后丢失已复现。
- 更新可用状态和播放失败界面采用明确标记的合成 API 响应，仅用于查看 UI，不代表真实 GitHub 发布、联网检查或真实编码兼容性失败。
- 原始截图与观察记录位于忽略目录 `build/ui-audit-vxROdu/`。截图中的视频、名称、媒体路径和数据均为测试资料。部分初轮隐藏窗口截图存在样式更新滞后或图片未完成载入；另显示真实 Electron 窗口复核，设置选中高亮正确，字幕弹层不透明且保持可读。这些隐藏窗口现象没有作为产品缺陷列入建议。
- 本轮不是全项目测试重跑，不把既有文档的测试结果当成本轮结果，也不评价本轮未重新测量的大库性能、长时间稳定性、真实 HDR/HEVC 解码或跳播速度。
- 未读取日常原视频目录，未打包、发布、修改版本号或改动冻结浏览器归档。本轮只新增审查文档；前一轮分页修改保留。

## 项目结构与主要流程

| 层次 | 当前职责 | 下一步关注 |
| --- | --- | --- |
| Electron | 无边框窗口、置顶、纯净播放、文件夹选择、原生文件操作、数据位置、启动与退出管理 | 导出也应有完整的桌面保存与完成反馈；维持受限 IPC 和后台退出约束 |
| React | 媒体库查询、目录树、剧集、片单、播放器、设置、任务与提示 | 理顺入口和状态，减少长页面中的寻找成本 |
| FastAPI / SQLite | 索引、元数据、队列、偏好、备份恢复、媒体供给 | 保持事务和所有权边界，逐步整理路由组织 |
| FFmpeg / 派生缓存 | 探测、缩略图、字幕转换、无损封装、显式确认的兼容转换 | 坚持原文件只读、缓存有界、取消与活动读者保护 |
| 验证 / 发布 | 后端回归、共享渲染器测试、真实 Electron 验收、标签发布 | 把常用桌面流程纳入持续验收，避免只靠浏览器组件测试 |

主流程为：添加目录 → 扫描索引 → 后台生成封面 → 浏览 / 搜索 / 分类 → 播放 → 保存进度 → 返回原浏览位置。辅助流程为：组织片单 / 编辑媒体 → 设置偏好 → 备份、恢复与迁移。

已有的分页、查询取消、结果缓存、目录树有界展开、缩略图后台让路、共享对话框焦点管理、原画权限保护和退出保存机制，均应作为迭代基线保留。无需把这些功能重新开发一遍。

## 优先处理的具体问题

### P1：桌面导出没有完整的完成反馈

`BackupTools.tsx` 用链接交出下载后立即清除任务，并提示“已交给浏览器下载……可在下载列表查看完成情况”。Electron 主进程未找到 `will-download` 下载生命周期接管；诊断导出也通过链接触发。这里确认的是应用内缺少目标路径、真实完成与失败状态反馈，不是断言文件一定保存失败。

建议：采用原生保存位置选择或接管桌面下载生命周期，展示保存中、已保存、失败与取消，完成后提供“在文件夹中显示”。允许大备份流式写入，不把多 GB 文件加载成 renderer Blob。保存取消不误报失败，后端任务与下载读者仍受保护。

验收：选择位置、取消、写入失败、大备份及完成定位均有真实 Electron 测试；应用只在真实落盘后宣告“已保存”。

### P1：整理媒体必须绕到播放器

`MediaActions.tsx` 菜单目前没有信息 / 封面编辑项；`MediaEditor.tsx` 和 `CoverEditor.tsx` 仅在 `Player.tsx` 中使用。修改名称或封面会进入与整理目的无关的播放流程，离线文件尤其不便。

建议：卡片菜单打开独立编辑对话框，复用现有编辑和封面模块。离线文件仍可修改库内元数据、导入本地封面；从源视频生成封面时明确要求文件在线。播放器里的编辑入口可以保留。

验收：从库内完成编辑不创建播放请求；收藏 / 进度更新不覆盖编辑草稿；切换视频、关闭或保存失败都有明确行为。

### P1：设置保存方式不一致，截图目录草稿会丢失

连播、续播、无损准备使用自动保存；截图目录需要点击保存。`ScreenshotSettings.tsx` 重新启用标签时重新读取已存配置，未保存输入被覆盖。本轮在真实 Electron 中修改输入、切到媒体目录再回来，复现草稿丢失，未出现提醒。

建议：自动保存项展示保存中 / 已保存 / 保存失败；需要确认或验证的目录输入保留显式保存，增加未保存状态、放弃草稿与切换 / 关闭保护。不要为了统一形式而把所有路径输入改成逐字自动保存。

验收：切换标签、关闭设置、重启和接口失败均验证；界面不得把未成功持久化的值显示为已保存。

### P1：计数与空状态的语义需要校正

`Pagination.tsx` 固定使用“个视频”；`SeriesLibrary.tsx` 把剧集分组总数直接传入。首用空库与普通搜索空结果也复用“暂无匹配的视频”。高级筛选的清除范围不包括所有搜索 / 目录条件。

建议：分页组件接受计数单位，分组显示“部剧集”、单集显示“集”、普通库显示“个视频”。空状态根据原因显示动作；提供全部条件摘要与统一清除入口，保留逐项取消能力。

验收：无根目录、根目录未扫描、过滤零结果、离线根目录、一个剧集多集、跨页末页都显示正确数量、单位和动作。

### P1：目录移除缺少对影响的说明

`Settings.remove()` 直接调用 DELETE；后端删除根目录注册，并把关联媒体标为 missing，原视频并不会被删除。风险是用户误解“移除”的库内影响，或误点后不知道如何恢复，并非源视频被删除。

建议：执行前展示路径、影响的视频数量和对库内记录的处理，或提供有语义保证的恢复注册操作。不要简单做一个只重新扫描、却可能丢失原目录关联的“撤销”。

### P2：工具栏、设置与任务入口需要收敛

800×620 下没有观察到主容器水平溢出，但顶栏换行、设置和片单内部滚动会消耗可用空间。播放偏好同时承载截图、悬停预览、后台封面和高级无损准备；任务分布在多个位置。

建议：以短路径和可理解的分组为目标整理。窄窗口把次要筛选收起；设置中将日常项与高级项分层；任务共用状态词、结果摘要和重试入口。保留以媒体内容为主的布局，不增加宣传区或常驻大面板。

## 建议迭代顺序

| 阶段 | 范围 | 完成标准 |
| --- | --- | --- |
| 第一轮：日常流程与反馈 | 桌面导出、独立单视频编辑、设置草稿保护、计数单位、空状态与目录移除说明 | 从界面能完成任务并确认结果；失败 / 取消有出路；没有额外播放请求或源文件改动 |
| 第二轮：全 UI 一致性 | 窄窗口工具栏、设置分组、筛选摘要、任务状态、统一确认与提示、片单批量操作、文档导航 | 深浅主题、最小普通窗口、长标题、离线与错误状态采用同一规则；保留焦点和快捷键行为 |
| 第三轮：可维护性与真实性能 | 播放器逻辑边界、样式归属、后端路由组织、真实媒体矩阵、长期运行和 CI 桌面流程 | 以可重复测量证明改进；相同 video 节点 / 来源 / 进度与画质不被界面改动破坏 |

第一轮可以再按“导出 → 独立编辑 → 保存和空状态”分别交付，避免一次同时重排所有页面和调整播放器底层。

## 工程侧配套建议

- `Player.tsx` 约 1,439 行，`app/main.py` 约 1,926 行，Electron 主进程约 560 行。已有播放控件状态、诊断、反馈等 hook；后续拆分应在此基础上继续，优先提取纯展示控件和明确的会话接口，避免再次搬动已整理过的 `usePlaybackChrome`。
- `styles.css`、`design-system.css`、`appearance.css` 与功能 CSS 叠加覆盖。逐模块明确基础、主题和状态样式的归属；修正时不再追加同选择器的覆盖补丁。不能只因为文件多就全面重写现有样式。
- 当前 Windows CI 普通推送选择了部分共享渲染器用例和 Electron 启动、纯净置顶、更新结果验收；并非所有已有桌面脚本都会运行。把目录添加 / 编辑、导出、设置草稿、返回库恢复这几条主流程纳入小而稳定的真实 Electron 验收集。
- 深浅主题、760×560 普通窗口、常用 DPI、长路径 / 标题、0 / 1 / 满页 / 末页、离线 / 错误 / 保存中构成 UI 验收矩阵。纯净播放可小于普通窗口，其弹层需单独验证；浏览器窄视口测试不能替代 Electron 桌面验收。
- 真正的性能项应测首次可操作、真实首帧、跳播目标准确性、源重载、缓冲、I/O 和资源回收。既有报告仍有 VP9/MKV 长尾及 HEVC/HDR 样本限制，下一轮补真实 Electron 样本；不要把合成 UI 审查、旧文档或暖缓存耗时当成新性能收益。
- 诊断导出可提供脱敏选项：保留技术信息，按用户选择隐藏本地路径与标题。仍允许完整本机诊断用于定位故障，导出不自动发送给任何人。
- README 当前仍有“从运行诊断进入关于”的旧导航表述，应与“标题栏 / 设置 → 帮助 → 关于”同步。文档只记录当前使用方式，不加入版本流水账。

## 暂不优先的方向

当前审查没有给出增加独立网页版、云同步、在线抓取资料、整体视觉重做或默认兼容转码的依据。虚拟滚动、替换播放器实现和帧级截图应先有对应的大库 / 编码 / 选图需求与测量，再独立评估。

所有播放优化继续遵循原文件直放 / stream-copy 优先；有损音频或视频转换保持显式授权，返回原画撤销权限；所有派生文件继续进入应用所有缓存并保护活动读者。

## 主要源码定位

- `frontend/src/main.tsx`：库入口、分类、搜索、筛选、卡片、空状态。
- `frontend/src/Pagination.tsx`、`SeriesLibrary.tsx`：分页计数单位与剧集视图。
- `frontend/src/MediaActions.tsx`、`MediaEditor.tsx`、`CoverEditor.tsx`：独立编辑入口的复用点。
- `frontend/src/Settings.tsx`、`ScreenshotSettings.tsx`：设置分组、目录移除与草稿保护。
- `frontend/src/BackupTools.tsx`、`Diagnostics.tsx`、`electron/src/main.ts`：桌面保存与导出反馈。
- `frontend/src/Playlists.tsx`、`PlaybackQueue.tsx`：片单与连播语义。
- `frontend/src/Player.tsx`、`ui.tsx`、`useModalDialog.ts`：播放器状态、对话框与焦点基线。
- `.github/workflows/windows.yml`、`electron/test/`：桌面验收覆盖。

本文给出审查结论与建议，不代表上述迭代已实施。
