# 封面缓存与多屏诊断验收

2026-10-17 本地源码迭代。不打包、不发布、不升版本号；保留原有工作区改动。
E:\downloads 视频只读。所有索引及封面测量使用隔离副本，未修改原媒体库或原视频。

## 变更

- 当前版本地址的封面使用 `private, max-age=300`；无版本、旧版本或非法版本继续 `no-cache`，
  404 保持 `no-store`。自定义封面保留打开的读取句柄，旧资源在读取完毕后才释放。
- 封面更换、重生成等已有操作更新版本地址，立即绕过旧缓存；不会为提速改动视频编码、尺寸或色彩。
- 基准分别记录逻辑请求、HTTP 缓存命中和 CDP `encodedDataLength`，不把三者混为磁盘 I/O。
  记录各 Electron 进程工作集、CPU、当前 DOM 图像像素及 JS 堆。GPU 进程工作集不是显存占用。
- MPV 诊断增加实际显示器范围/工作区/缩放及最近 16 次布局；记录有界且随会话释放，
  不包含源路径、标题或显示器名称。原生退出过程中不再记录已关闭窗口。

## 实机复现步骤

1. 设置选择 MPV，播放已知无内置黑边的视频；不同缩放显示器之间移动普通窗口。
2. 分别进入/退出纯净播放、旋转、最小化恢复；观察视频边缘和控件点击区域是否对齐。
3. 若异常，先从原生设置面板“复制播放诊断”，记录操作顺序，再还原窗口。
   对照 `displays`、`recentLayouts`、`layoutPending` 和源加载次数。分享桌面截图前遮挡标题。
4. MPV 截图正常只说明已解码画面正常，不能代替桌面叠层与窗口位置验收。

## 重复测量

```powershell
node electron/test/desktop-cover-stress.mjs <授权索引> --passes=36 --hardware-gpu
node electron/test/desktop-cover-stress.mjs <授权索引> --passes=36 --hardware-gpu --phase=scroll
node electron/test/desktop-cover-stress.mjs <授权索引> --passes=36 --hardware-gpu --walk
```

不带 `--hardware-gpu` 为历史软件 GPU 对照，不与硬件模式混算内存收益。
`--phase=pages` 只翻页，`--phase=scroll` 只滚动，默认 mixed；`--walk` 遍历全部页面再返回。

## 下一步建议

1. 用户实机多屏混合 DPI 验收，异常时先保留本轮新增诊断，不根据过后正常状态推断根因。
2. 延长全库跨页到小时级并增加多次重新开关播放，观察 GPU/渲染工作集是否继续增长，
   再决定是否需要按图像像素预算做更精细的封面缓存；当前不引入未经测量的全局缓存清理。
3. 在相同窗口与缓存条件下做更长的 MPV 播放/后台任务负载；HDR 和长 HEVC 缺样本项保留未验证。
