# MPV 打开速度与启动清理验收

## 本轮范围

最终构建 `8263414e2a4ed509`，版本保持不变。未打包、发布或推送。

先测量再调整：新增启动分段计时，区分元数据/占用预约、窗口创建、控制层加载、引擎初始化、原生画面就绪及嵌入。发现原生画面就绪阶段约 210–240ms，并非整个阶段都属于纯等待，它也包含 MPV 创建视频输出窗口及 GPU 初始化。

本轮没有增加驻留解码器或窗口池。关闭仍退出自有 MPV 进程，确认退出后释放文件保护。优先通过并行与就绪检测消除多余串行耗时，避免直接引入旧视频残留、跨会话命令或文件占用风险。

## 调整

- 控制层文档加载与 MPV 初始化并行；二者都结束后才进入画面层级与嵌入流程。
- 使用 `Promise.allSettled` 等待两个分支，不让迟到分支在宿主销毁后继续工作。双重失败优先保留解码器原始错误，不以次要导航取消错误覆盖。
- 启动完成前后核对会话和窗口仍然有效，退出或取消的会话不返回成功。
- 原生画面就绪检测从固定 100ms 重试改为 15→20→25…40ms 的有界退避。总预算约 1 秒，单次 HTTP 请求也限制在剩余预算内；权限等非 409 错误立即失败。
- 关闭时等待在途原生窗口就绪任务结束，再释放其 owner 和销毁窗口。
- 补充控制层进程退出的兜底：已有 3 秒心跳检查自有 WebContents 的崩溃状态与进程存活。存活探测只使用信号 0，只有明确 `ESRCH` 才判断 OS 进程不存在，`EPERM` 等未知状态不误判；PID 来自本应用的控制层，不接受外部输入。异常通知失败也不能阻断解码器清理。

原文件直放、硬解选择、精确定位、截图分辨率和色彩参数未改变；没有新增转码或自动放宽画质权限。

API 语义参考：[Electron WebContents](https://www.electronjs.org/docs/latest/api/web-contents#event-render-process-gone)、[Node.js 信号 0 存活检查](https://nodejs.org/api/process.html#processkillpid-signal)。没有自动终止仍存活但暂时无响应的控制层。

## 应用内性能对照

`native-app-performance.mjs` 从可见 Electron 媒体库封面打开视频，**等待主页面确认嵌入完成，并核查解码重启和实际时间推进**。不是直接调用 open/seek API 的独立引擎测试。

本轮新增主页面就绪等待，因此以下打开墙钟不能直接与上一轮只等解码确认的墙钟数据比较。自动化点击、断言轮询也有开销，不代表精确的输入到光子延迟。

每个实际样本三次打开，本机短测中位数：

| 样本 | 点击封面至应用播放就绪 | 原生启动任务总耗时 |
| --- | --- | --- |
| 4K VP9 MKV，ID 1 | 912 → 764 ms | 412 → 274 ms |
| 4K H.264 TS，ID 62 | 879 → 675 ms | 382 → 241 ms |
| 4K AV1 MP4，ID 2358 | 851 → 781 ms | 380 → 257 ms |

- 对照：`build/native-app-performance-5wmKfK/acceptance.json`。
- 调整后：`build/native-app-performance-quUQDF/acceptance.json`。
- 该组性能测量后又补充异常清理保护，未改变初始化与解码策略；不将所有最终代码变更都冒充独立性能测量。
- 连续快进最终目标确认仍约为 MKV 69ms、TS 69ms、MP4 113ms，没有撤销上一轮连续定位优化。
- 三个样本均使用 `d3d11va`，每会话一次源加载、0 次缓存暂停、0 次纠偏，分辨率与原索引一致，源文件大小与修改时间不变。
- 8K 样本 ID 1388 追加三轮实际应用验证通过，原始 7680×4320、硬解、跳播及时间推进正常，0 次缓存暂停和纠偏。报告：`build/native-app-performance-E2weMw/acceptance.json`。没有该 8K 样本的优化前同条件基线，不宣称其提速幅度。

不是冷盘、长时间、多机器或全部视频基准；应用尚未达到所有格式零等待。

## 正确性与异常验收

- `native-coordination.mjs`：明确检查退避序列而非易受 CI 负载影响的墙钟阈值；非 409 权限错误不重试；存活检查区分 ESRCH/EPERM，且只发送信号 0。
- `native-startup-recovery.mjs`：控制层失败、解码器延迟启动；两个启动分支都失败；保留原始解码错误；退出确认前保留文件保护，完成后可从应用界面重试。生成样本哈希及修改时间不变。
- `native-embedded.mjs`：嵌入原生画面、透明控制层、全屏、纯净播放、最小化恢复及移动；125% DPI 的桌面合成截图检测到实际测试图案。不是多屏混合 DPI 或真实物理键盘验收。
- `native-player.mjs`：截图、字幕音轨、重复打开、退出及源文件保护。该测试暴露控制层进程故障后事件未及时送达、MPV 继续运行的边界，修复后仍保留真实崩溃注入和 20 秒断言，不通过增大时限或删除断言掩盖问题。
- `native-app-flow.mjs`：用户指定 4K AV1 样本的应用内鼠标定位、相对快进、主窗口快捷键转发与时间推进通过；只读源哈希/修改时间不变。
- 控制栏及启动生命周期的显式组件回归：19 项通过，不能代替原生桌面验收。
