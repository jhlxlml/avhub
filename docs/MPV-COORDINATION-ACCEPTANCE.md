# MPV 播放协调与应用内回归

## 本轮调整

- 相对快进/快退由主进程基于最新待定位目标累加，不再使用渲染层滞后的播放时间计算绝对位置。
- 旧跳播失败不再清除新目标；保留目标精度检查和有界纠偏，不把命令 ACK 当作目标画面已解码。
- 区分定位片尾与自然结束；暂停定位片尾不误触发连播。启动响应前的结束、关闭事件保留至会话建立后处理。
- 慢时间查询只有在先观察到目标附近时间时，才计入正常播放推进量；不凭等待时长放宽定位精度。
- 截图等待已接收的画面变更操作；取帧期间拒绝冲突操作，PNG 写入完成后的保存阶段允许继续跳播。关闭有界等待保存，解码进程确认退出后才释放文件占用保护。
- 周期进度保存和播放活动状态合并中间请求，关闭时仍保存最终状态。
- 窗口布局确认成功才记为已应用；同一布局瞬时失败最多重试三次，保留最新尺寸而非堆积旧尺寸。
- 控制层按会话和单调修订号过滤旧快照，避免初始查询覆盖新状态。

原文件直放、精确定位和画质参数未降级，没有新增转码、缩放、降位深或 HDR 映射。

应用流程覆盖：连续两次相对快进、主窗口快捷键转发、暂停定位片尾不连播、鼠标定位后时钟继续推进、自然结束后连播下一项、返回媒体库关闭原生会话。

实际媒体模式：`node electron/test/native-app-flow.mjs <只读索引绝对路径> <媒体ID>`。
该模式复制索引到隔离目录、清除文件变更权限，不扫描或修改源媒体；记录前后哈希与修改时间。默认无参数生成两个隔离合成样本。

本轮实际样本：用户提供的 `4-model-tina-bikini-2-at-busqueen.mp4`（4K AV1 60fps，索引 2358）。应用内相对快进、暂停点击定位与恢复推进通过；源文件仅加载一次，定位误差小于 0.5 秒，源文件哈希/修改时间不变。真实样本不等待自然片尾，片尾连播由合成样本验证。

测试检查目标时刻和解码端时间推进，不以隐藏提示或保留旧画面证明更快。本轮不是全格式性能基准，不宣称所有跳播零缓冲。

## 保留验收项

- Playwright 的窗口渲染器输入不能证明真实 Windows 键盘焦点；点击原生画面后、Alt+Tab 返回、最小化恢复后的物理键盘响应仍需交互桌面验收。
- 多屏混合 DPI、跨屏拖动、HDR/10-bit 与长 HEVC 样本未在本轮重新验收。
- 当前自动化结果不能代替实际桌面合成画面的肉眼检查。

默认本地应用流程：`npm run test:electron:mpv:app`。原生运行库 CI 的应用流程已加入可选 MPV 验证任务；普通组件回归加入启动竞态测试。本轮未打包、发布或提升版本。
