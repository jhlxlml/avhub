# 多格式跳播：真实数据链路优化

本轮接续 TS 索引直读，验收以目标画面实际可见、视频源重载次数、真实显示层和资源释放为准。没有调整缓冲提示的显示阈值，也没有通过降低分辨率、画质或跳到附近关键帧代替精确寻址。

## 核查与取舍

- 原文件直放：MP4、MOV、WebM 以及浏览器可解码的 MKV 继续直接使用标准 HTTP Range。没有为了统一处理强制转码或封装。
- 需要封装的 H.264：旧路径在尚未生成或已回收的目标上销毁 Hls.js / MediaSource，停止旧 FFmpeg、准备新窗口并重新加载 video。保留上一张画面只能避免黑底，不能消除这段实际等待。
- 原文件传输：此前 FileResponse 不监听请求断开。旧的开放式 Range 被浏览器取消后，服务端仍可能读完剩余视频；在 Windows 上异步关闭自身也可能被取消而留下句柄。现在取消过时读流，并保护关闭操作完成。单范围、后缀范围、多范围、If-Range、HEAD 仍使用标准语义；读块限制为 1MiB。
- VP9 / AV1 直放：长 GOP 和解码器本身仍可能有真实等待。真实 4K VP9/MKV 在参考应用也测到约 668ms 中位数；参考应用没有显示加载提示，不代表瞬间完成。本轮没有把这些文件强制转成有损 H.264。
- 尝试过 Matroska 前置 Cues 虚拟文件，但实测收益有限，未保留该实验实现。不以增加复杂度替代可验证的性能收益。

## 新路径：索引按需封装

适用 H.264 的 MKV、AVI、MOV、MP4/M4V、FLV，且当前播放确实需要封装（例如原文件不兼容或选择另一条音轨）。直接播放仍优先；显式画质和强制转码继续遵守原选择。

1. 首次播放用 FFprobe 记录关键帧显示时间 PTS、解码时间 DTS 和容器起点。索引在应用数据目录 `remux-index/` 按源路径、大小、纳秒修改时间校验复用，不在添加目录时批量预处理。
2. 提供完整时间轴的 VOD 清单，目标片段由短 FFmpeg 任务按需封装；不等待顺序封装到目标、不复制整部视频、不重建视频源。
3. 视频使用 `-c:v copy`。AAC 保留编码，非兼容音频单独转 AAC。画面编码、分辨率与原片相同；单元测试比较原片与封装片段的解码像素。
4. B 帧不能只按 PTS 设置输入 `-ss`，否则可能带上前一个 GOP、丢掉目标 GOP或错位。按 DTS 做输出裁切，保留并归一化原时间戳。缺失的首 DTS 用后续关键帧重排序延迟推导，AVI 缺失 PTS 使用 `genpts` 补全。
5. 首段不执行输入 `-ss 0`，避免非零流起点的解封装器跳过开头。已验证非关键帧目标、10 秒 GOP、B 帧、首画面和暂停跳播，不用“快但不是目标帧”验收。
6. 每会话串行生成、复用分片，缓存目标为 256MB 或更低的配置限额。单个超大 GOP / 已被 HTTP 读者打开的片段可以暂时超出；退出取消探测和封装，并清理专用会话目录。
7. 索引不适用时仅回退一次到原无损视频封装，保留所选音轨、画质、位置和暂停状态；不能解析源编码时仍有明确错误或兼容转码，未改为静默降画质。

`streamcopy`、寻址、时间戳保留及 `genpts` 的约定参考 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-all.html)。

目标画面耗时使用 `visibleMs`：目标帧确实呈现且保持层已撤下才完成；同时保留原始帧回调耗时 `ms`。新增媒体实际接收字节计数，避免只统计提示框。按动画帧采样的无画面/纯黑检查不能检测每个小于一帧的瞬间；源片暗场也不能直接算播放故障。

## 边界

- 全部原片直放仍由浏览器解码。4K VP9 / AV1、长 GOP、软件解码与驱动差异可能继续决定速度；本轮未替换原生播放引擎。
- 新路径只处理 H.264 封装，不覆盖 HEVC / VP9 / AV1 的重编码。既有 CRF、原分辨率和 HDR 映射策略未降低。
- 超长、损坏、时间戳跳变、无法可靠恢复关键帧时间轴的文件保留回退。探测和单片封装各有 30 秒上限。首次索引真实增加启动时间，之后复用小索引；本轮不承诺某个通用冷启动耗时。
- 真实长 HEVC、HDR / 10-bit 和更多旧 AVI / WMV 编码样本仍未充分验证；合成 H.264 AVI 通过不代表所有 AVI 都能免转码。
- 无 PTS 的 AVI 重建时间戳可能与完整解码器的最佳显示时间差一两帧。测试按原始关键帧像素及 ±120ms 的时间窗校验，拒绝跳过整个 GOP 冒充正确寻址；不承诺这类源具有逐帧精确的原始时间轴。
- 外部画中画不包含网页保持画面层，仍取决于浏览器自身的视频显示。
