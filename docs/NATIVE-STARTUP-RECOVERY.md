# 原生播放启动失败与恢复验收

## 问题和修复范围

用户遇到原生播放启动失败后，界面只显示“原生播放器仍未退出，保留文件占用保护”。代码中，启动异常处理直接等待退出清理；如果清理也失败，其异常会覆盖最初的启动错误。

- 现在保留最初错误，并附加清理尚未完成、文件保护仍保留的说明。重复重试不叠加重复说明。
- 已创建进程的 `error` 事件不能证明进程退出：终止失败也会产生该事件。只将无 PID 的启动失败视为未创建进程；否则等待退出证据，不能因此提前释放文件保护。
- 失败会话保留所有权。重新播放先重试清理，确认退出后才能启动新会话。返回媒体库和切换现有播放器同样不能绕过清理。
- 新的 `recover` IPC 意图仅接受受信任的主窗口，拒绝正在启动或正常使用中的会话；没有新增任意 PID 终止接口。
- 界面启动失败时不再持续显示“正在准备原生播放”，并去除该错误中的 Electron IPC 包装文本。
- 日志记录启动阶段和清理未完成状态，不记录源路径或原始错误里的私人信息。

没有修改解码器、硬件加速、封装、画质、分辨率、色彩或原视频。未放宽文件操作保护，也不以自动转码作为异常回退。

## 限制和后续定位

本次没有复现最初导致启动失败的 GPU、IPC 或进程退出异常，不能宣称其底层原因已根治。修复的是已确认的错误覆盖、错误退出判断和失败恢复链路。真实样本通过也不代表所有驱动、冷启动或长时间运行均已验收。若再发生，利用新的启动阶段日志和保留下来的首个错误继续定位；不得为消除提示而释放仍可能被进程使用的文件。

CI 配置已加入无运行库单元回归；实际 MPV 的恢复测试放在需手动启用的 native-runtime 作业。未推送、打包或触发发布。
