# TS 随机跳播：消除视频源重建与黑屏（2026-10-04）

## 本轮定位

前一轮调整缓冲提示解决了闪提示，但没有消除 TS 在未发布/已回收位置跳播时的解码器重建。

旧路径：点击进度 → 等待 120ms 合并请求 → 结束旧 FFmpeg 任务 → `Hls.destroy()` → 删除 `video.src` 并 `video.load()` → 新建封装窗口 → 新建 MediaSource → 解码目标帧。清空视频源是这类短暂黑屏的实质原因。即使不显示缓冲提示，这段空白仍然存在。

本轮没有继续调整 350ms 提示阈值，而是更换兼容 TS 的数据与解码器生命周期。

## 新实现

- 针对 H.264 / AAC（或无音频）的标准 188 字节、单节目的 `.ts`，用 FFprobe 建立关键帧时间及原文件字节位置索引。只有首次播放需要建立；索引存于应用数据目录 `ts-index/`，以后以路径、大小、纳秒修改时间校验并复用。不在扫描时批量读取所有视频。
- 生成完整时间轴的 VOD 清单；每个虚拟分片只读取原文件中一个关键帧区间，补上取自原文件的 PAT/PMT 初始化包。部分录制文件不在每个关键帧前重复这些包，不能简单按文件大小均分，也不能假设每个区间原本自带初始化信息。
- 跳播交由现有 Hls.js / MediaSource 按需加载目标分片，保持同一个 video、视频源和解码器，不重建封装任务、不等待顺序封装至目标、不在磁盘复制整部视频。
- 原始视频/音频编码包逐字节保留，浏览器仅解封装，没有视频重编码、缩放、CRF 或色彩映射调整。请求指定音轨、显式转码/画质，以及不符合索引条件的源文件仍走原兼容路径。
- 寻址时暂存最后一张已解码画面。只有目标帧实际到达、浏览器结束寻址且有可显示数据时才撤下。暂停寻址同样处理，不用计时器提前宣布成功。失败/退出会释放；不会用无限冻结掩盖播放失败。该画面交接也改善其他格式跳播时浏览器短暂清空当前数据的黑底。
- 点到当前进度不再触发多余的 MSE 寻址；点击画面仅控制播放/暂停。
- 索引使用可取消的异步任务，不持有数据库/播放管理锁等待全文件探测。关闭、闲置、取消及过期令牌保护保留；源文件变更时拒绝使用旧索引。索引/解析不支持时先回退复制视频编码的兼容封装，不直接降画质。

VOD 清单、时间轴和 TS 初始化要求按 [HLS 标准](https://www.rfc-editor.org/rfc/rfc8216.html) 实现，浏览器侧复用 [Hls.js 的 VOD 寻址机制](https://github.com/video-dev/hls.js/blob/master/docs/API.md)。虚拟分片读取原文件范围，不是将原 TS 直接交给 `<video>`。

## 首次播放与边界

本样本最终首次播放约 2.5 秒，包含建立关键帧索引；这是新的首次成本，不隐藏它。后续复用几十 KB 的索引，不再遍历原视频。缓存校验与损坏重建已有测试。本轮未把索引费用摊到媒体库批量扫描，避免添加大量目录时争抢磁盘。

当前索引路径不覆盖 HEVC 转码、192 字节 M2TS、损坏/截断 TS、多节目 PAT、时间戳倒退、显式音轨切换。探测最长 30 秒，不能索引的文件保留兼容回退及可见错误反馈。不引入 MPV、不预转码全库、不修改原文件；不是所有浏览器解码限制都已消除。画中画的外部窗口由浏览器控制，网页上的临时画面保持层不进入该窗口。
