## 2. 已确认的功能缺陷

P1：优先解决播放正确性或数据关联错误。P2：随后解决交互正确性。

| 编号 | 优先级 | 已复现的问题 | 原因与修复方向 |
| --- | --- | --- | --- |
| B01 | P1 | 非零起点的重建播放流，字幕错位或迟迟不显示 | 字幕只应用用户延迟，没有减去播放流 offset；需要统一原视频时间与流内时间，并随流重建更新字幕 |
| B02 | P1 | 恢复其他媒体库备份后，同 ID 视频沿用旧封面 | 缩略图仅以数字 ID 命名，恢复时仅检查文件存在；需要按来源指纹验证或在恢复后失效重建 |
| B03 | P2 | 已有播放列表时填写“或新建列表”，视频却加入旧列表 | 已选 targetId 优先，忽略新名称；应明确区分“加入已有列表”和“创建并加入” |
| B04 | P2 | 编辑标题尚未保存，点击收藏后草稿被重置 | 收藏返回的新媒体对象包含新的 tags 数组，触发编辑器重置 effect；需要独立草稿及脏状态保护 |
| B05 | P2 | 暂停时切换画质，视频自行开始播放 | 重建播放函数默认 autoplay=true；切画质和音轨需要保留切换前的暂停状态 |
| B06 | P2 | 空结果页点击“查看全部视频”，仍没有视频 | 仅清除搜索/目录/分类，遗留格式、观看状态及时长筛选；需要完整清除，或准确命名动作 |
| B07 | P2 | 设置弹窗打开后焦点仍在背景，Esc 无法关闭 | 缺少焦点进入、约束、恢复和统一关闭逻辑；播放列表也应复用同一弹窗基础组件 |

### B01：字幕时间轴

复现：打开测试视频→暂停并跳到 20 秒→选择 480p，生成 offset=20 的播放流→加载原片 20–22 秒字幕。视频流内时间约 0.23 秒，字幕 cue 仍为 20–22 秒，activeCues 为 0。用户延迟设置无法根治起点变化。

位置：[Player.tsx](D:/AI/codex/avhub/frontend/src/Player.tsx:427)。验收应覆盖续播、未缓存位置跳转、画质切换、音轨切换，以及跨越流起点的字幕 cue。

### B02：恢复备份封面串库

隔离复现：备份媒体库 B，当前媒体库 A 的 ID=1 存有 A 的 JPEG 缓存；恢复 B 后数据库标题和路径已变成 B，但 /thumbs/1 返回的仍是 A 的原缓存字节。

位置：[main.py](D:/AI/codex/avhub/app/main.py:694)。这里不是数据库恢复失败，而是数据库与缓存失去来源关联。普通扫描在元数据未变、旧 JPEG 有效时也可能跳过重新生成，不能只依赖“提示刷新”修复。

### B03：新建播放列表动作

复现：已有 Existing 列表→选择视频加入片单→填写 New list→添加。结果 Existing 增加视频，New list 未创建。

位置：[Playlists.tsx](D:/AI/codex/avhub/frontend/src/Playlists.tsx:61)。验收应分别覆盖已有列表、新建并加入、重名、网络失败、重复点击。

### B04：编辑草稿保护

复现：打开媒体信息编辑→输入新标题但不保存→点击右上角收藏。标题恢复成旧值，无提示。

位置：[MediaEditor.tsx](D:/AI/codex/avhub/frontend/src/MediaEditor.tsx:16)。应按媒体身份初始化，而不是任何媒体对象变化都重置；切换视频或退出时有未保存内容需要提示。标记已看等返回完整媒体对象的动作也需要相同保护。

### B05–B07：播放与弹窗状态

画质切换实测会将暂停变成播放；音轨切换存在相同默认参数路径，尚未单独实测。位置：[Player.tsx](D:/AI/codex/avhub/frontend/src/Player.tsx:592)。

空结果复现地址包含 q=not-found 与 format=wmv。按钮点击后搜索清空，但格式仍为 wmv。位置：[main.tsx](D:/AI/codex/avhub/frontend/src/main.tsx:287)。

设置弹窗已实测焦点没有进入对话框，Esc 后仍存在。位置：[Settings.tsx](D:/AI/codex/avhub/frontend/src/Settings.tsx:84)。除焦点控制，还应统一背景滚动锁定、忙状态下关闭策略和关闭后焦点恢复。

## 3. 源码确认的限制与待验证风险

这些问题与上面的用户交互缺陷分开处理；未实测的后果不视为已经发生。

### 长片缓存限制

[playback.py](D:/AI/codex/avhub/app/playback.py:143) 在单次播放缓存超过 2GB 后停止生成流并提示重试。当前 FFmpeg 持续向前生成全部分片，没有滚动删除或前向生成节流。

这意味着高码率重封装或长片可能中途被上限打断，而不是仅占用更多磁盘。建议设计有界前向缓冲/任务节流和缓存回收策略；不能简单删除旧分片而破坏现有清单与回看。应测试 1–2 小时播放、暂停后继续、两播放任务、异常退出和重启后的残留缓存。本轮未进行长时真实 4K 播放测试。

### 本地服务安全边界

Electron 模式已有随机会话、Host 校验、隔离上下文、禁用 Node、sandbox 和导航限制，应保留。浏览器启动模式没有默认会话令牌；中间件在令牌为空时直接放行，隔离请求中的非本机 Host/Origin 也得到放行结果。绑定 127.0.0.1 不等同于所有跨站访问边界已经解决。

建议让两种启动模式都具备本地主机校验和敏感写操作的来源/会话校验，同时明确拒绝不需要的 Electron 权限。这里是代码与配置层面的加固缺口，不代表已证明真实浏览器可完成任意跨站攻击；仍需单独的安全测试。[Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

另外 frontend/index.html 把 frame-ancestors 写在 meta CSP 中；该指令不支持 meta，需要通过 HTTP 响应头设置。不要误以为目前已经禁止了外站嵌入。[MDN 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)。

### 大库性能

SQLite 连接统一经过全局 DB_LOCK；搜索使用包含匹配，组合筛选有计数查询，队列定位包含窗口排序。对大库可能成为瓶颈，但本轮没有测出具体卡顿，不应仅凭源码断言需要替换数据库。

建议使用可重复的 1 万目录/10 万视频数据集，记录列表、搜索、目录切换、队列定位的 p50/p95、扫描内存、查询计划与播放进度保存延迟。先测量，再决定新增索引、计数缓存、全文检索或缩短锁范围。当前媒体已分页，不必无条件再加虚拟列表。

### 数据路径与版本可见性

浏览器启动默认使用项目 data，Electron 开发启动默认使用用户配置目录；便携包优先使用 EXE 旁的 AVHub-data，写入失败时另有回退。用户切换启动方式可能看到不同媒体库。

建议“关于/诊断”展示实际数据路径、启动模式、源码/构建标识、API 协议版本、FFmpeg 版本；提供明确的备份导入流程，不要静默合并两个数据库。现有 JSON/HTML 响应识别已有保护，但应增加真正的前后端版本握手，而不是只等接口返回 HTML 才发现版本不一致。

### 工程与维护

- Player.tsx 和 app/main.py 承担过多职责；建议逐步拆出播放时间轴、字幕、播放会话及持久化服务，不进行一次性大重写。
- 通用 API 没有统一超时策略；页面取消请求和请求超时是两回事。需区分查询超时、扫描任务、上传恢复备份，不能让所有请求使用同一个短超时。
- 设计变量已存在，但通用选择器与多层样式覆盖较多；新增功能仍容易引入样式冲突。建议组件局部化，并逐步收敛重复规则。
- package-lock.json 已存在，可以使用 npm ci；部分依赖声明仍是 latest，Python 安装版本区间较宽。建议锁定验证过的依赖组合，不要把升级依赖与业务大改混在同一批。
- 当前目录未发现 Git 仓库。建议建立版本记录及测试门禁，保证迭代可比较、可回退；本轮没有自行初始化 Git。
- TypeScript 构建在根目录生成 vite.config.js、声明文件和增量构建文件，建议统一输出目录及忽略规则；Vite 配置加载和 HLS 大 chunk 有构建告警。HLS 是按需加载，chunk 大不等于首页一定卡顿。
- Electron 测试仍以项目根为 CWD。为避免先前出现的异常空目录污染再次影响源码目录，建议为原生测试隔离 CWD、使用绝对应用路径；本轮没有再次看到乱码目录，也没有重新运行原生窗口 UI 自动化。

## 4. UI 与体验建议

截图核查覆盖媒体库、设置、播放列表、播放器详情和窄窗口。主题色、深色面板及 SVG 线宽已基本一致，当前问题是细节与交互，不建议推翻视觉语言。

1. 统一 Modal、Button、IconButton、Popover、Toast、EmptyState 和 Loading 基础组件。优先统一焦点、Esc、禁用、加载和错误状态，再统一圆角、间距和字号。
2. 播放页信息分层：播放与队列为第一层；字幕、播放信息、快捷键为按需层；媒体编辑是低频层。字幕设置目前主要在视频下方，纯净播放/全屏操作不便，建议增加控制区字幕图标弹层，仍把画中画与视频全屏放在最右侧。
3. 窄窗口按“播放/音量/进度→画质/倍速→更多功能”排序，减少不稳定换行。旋转、缩放还原、截图等可放在统一更多菜单，但常用功能保持一键可达。
4. 文案标准化：MP4 而非 .MP4；“个视频”而非在不同页面混用“部/个”；未知季集号用“未设置”，不要展示问号。重封装标签建议明确“视频无损”，因为音频可能转换为 AAC 双声道，不能让用户理解成整个文件完全无损。
5. 播放列表可按阶段增加缩略图、离线标识和更清晰的当前播放项。长名称统一截断、提示与编辑展示方式，避免窄窗口标题断词。
6. 错误状态要给出具体恢复动作：重新定位、重新扫描、重试播放、查看诊断。正常状态保持紧凑；继续保留隐藏控制栏时键盘操作不唤醒控件的用户设定。

## 5. 功能边界与后续扩展

“电影/剧集”目前主要是文件级分类与季集元数据，并非完整的剧名→季→集聚合影视库；离线手动自定义封面也尚未形成完整流程。这属于可规划能力，不应与当前 bug 混为一谈。

等基础稳定后，再考虑：稳定的剧集组 ID、剧集/季聚合、批量编辑、离线自定义封面、重复文件提示和更明确的无法识别类型。仍不提供移动/重命名/删除源视频，也不引入联网刮削或账户同步。
