# 第四批：规模与媒体库能力（2026-10-03，未打包）

本批遵循 `AUDIT-2026-10-02.md` 第四批范围，不引入 MPV、联网刮削、源文件管理或新 EXE。数据库、封面与测试缓存均与原视频分离。

## 入口与行为

- **剧集 → 按剧集归类**：剧名卡片 → 季 → 单集。服务端分页，支持目录和剧名搜索、特别篇（季 0）、未设置季、离线集提示；地址栏保留分组、季和页码，播放返回仍在原列表。默认文件级剧集浏览不变。
- 分组使用持久化 ID，单集改标题、分组改名、重新启动和重新扫描不打散组。自动推断按媒体根目录隔离同名剧，避免不同目录的同名作品自动串集。跨根合并可明确选中相关视频，用批量剧名归组。无法确定的作品仍需用户手动整理。
- **文件级媒体库工具栏 → 批量整理**：跨页勾选、选中本页、清空选择、编辑所选，每次最多 500 个明确 ID；切换搜索或成员筛选会清空选择，分页/排序不会。支持类型、剧名、季、评分、收藏、已看与标签增删，不批量改写文件名，也不自动推断连续集号。
- 批量请求在单个事务中提交；索引消失、非法分组或标签合并超过 30 个时全部回滚。收藏/观看状态使用目标值，不使用切换操作；标签去重。手动已看不伪造观看进度。写入超时沿用“可能已提交，先刷新确认”的规则，不自动重放。
- **播放页 → 编辑媒体信息 → 选择本地封面**：JPEG/PNG，最大 8 MB / 2000 万像素，保存为缓存 JPEG（最长边不超过 960），不改原图片或视频。可恢复视频截图。导入/恢复不覆盖未保存的元数据草稿。
- 封面采用独立 UUID 和原子发布；校验签名、实际解码与像素上限，拒绝 SVG/HTML/远程链接。响应先持有文件句柄，避免同时恢复封面时删除尚未开始读取的缓存；释放后清理无引用的旧封面。只清理应用自身命名规则内的缓存文件。
- SQLite 备份不包含图片；同库且源指纹/封面引用相同可复用仍存在的缓存，不同库或缓存丢失时清除封面引用，不错误展示另一视频的图片。完整便携迁移须保留整个数据目录，包含 `covers/` 和 `thumbnails/`。

## 性能方案与可重复测量

运行 `npm run benchmark:library`（默认 1 万根目录 / 10 万视频 / 7 次重复），或：

```powershell
python scripts/benchmark-library.py --rows 100000 --roots 10000 --repeats 7 --label my-machine
```

脚本在新临时目录建立合成数据库，不读取实际媒体库、源视频或 NAS。包含热点根下 1 万子目录、万条片单、收藏/剧集/标签分布；记录 p50、p95、JSON 响应大小、Python 查询峰值和执行计划。报告以唯一文件名保存到 `build/library-benchmarks/`。

测量范围为本机热缓存下的 Python API 查询，不等于浏览器端到端时延、首次扫描、冷盘读取或真实 NAS 性能。Python 峰值不包含 SQLite 原生内存或整个进程内存。

改动：

- 最近观看表达式排序索引，以及收藏/剧集专用部分索引，消除大库分页时的额外排序。
- 万条片单不再为每次定位重复执行完整 ROW_NUMBER/LAG/LEAD 窗口计算；使用有序 `(position, media_id)` 索引定位邻居，保留搜索原始序号、离线项、相同 position 与跨页行为。
- 剧集 ID 索引保证单组查询有界；迁移后旧 ANALYZE 统计可能仍将 `series_id` 视作全 NULL，因此未分组补齐与单组/封面查询显式使用对应索引。没有在每次查询时重建统计或索引。
- 全库包含搜索的 COUNT 避免沿最近观看索引进行随机堆访问；只有结果可全部容纳于一页时采用物理扫描加小集合排序，广泛命中继续使用原有排序索引。目录、收藏等选择性筛选保留原查询计划；LIKE 转义、排序和分页结果均有回归验证。

最终测量和验收结果在本文件末尾记录。没有宣称所有查询都加速；名称排序、标签包含搜索、进度写入仍须看各自数据。索引会增加数据库空间和写入成本。当前保留 SQLite LIKE 字面包含语义，未引入会改变中文/短词匹配规则的 FTS。

## 验证与边界

- 新增隔离后端测试覆盖迁移幂等性、分组稳定性、跨根归组、特别篇/未知季、离线集、分页、改标题后的下一集、批量范围与回滚、原视频哈希不变、实际 PNG 解码、封面重置、极大图像与无效输入、缓存路径防越界、备份来源校验、扫描后自定义封面保留。
- 新增网页测试覆盖 1000 集的有界聚合、跨页批量编辑与刷新、错误重试状态、季筛选 URL、分组改名与播放返回、封面草稿保护、390px 弹窗宽度与 Esc。
- 原生权限策略、设置持久化和退出策略保持回归；不改变透明控制栏、画中画/全屏布局、纯净播放和键盘不唤醒控件的设定。
- 构建仍有既有 Vite 配置加载与 HLS 大 chunk 警告。HLS 仍按需载入，没有为消除提示随意改打包配置。
- 尚未验证百万真实文件、冷盘/断连 NAS、万目录实际完整扫描、真实 4K 多 DPI 显示或最终便携迁移。本批不据此宣称“全部格式完美播放”。
- 后续优先补真实大库样本与目录/文件指纹扫描测量，再决定是否需要 FTS、统计维护、扫描内存分批或重复文件提示。不要因完成合成查询基准就立即打包。

合成数据库从 56,303,616 增至 64,094,208 字节（约 +13.8%，包含新列、分组和索引）；首次补齐 25000 条未分组剧集约 481 ms，后续仅查询未分组 partial index，不重复补齐已有条目。
