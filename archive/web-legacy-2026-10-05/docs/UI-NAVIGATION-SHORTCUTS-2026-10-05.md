# 标签切换与进度条快捷键修复（2026-10-05）

构建：`9bc09050f3f964bf`。本轮不打包、不推送 GitHub，不修改源视频。

## 进度条快捷键

问题是播放器的输入保护规则只允许 range 输入框上的 Space / K；鼠标点进度条后，其他快捷键会被该规则直接返回。

当前区分焦点来源：

- 鼠标/指针点击播放器滑块后，Space/K、J/L、M、R、C、F、W、P、N 继续走播放器快捷键。
- 指针聚焦滑块上的左右键快退/快进 5 秒，上下键调音量。
- 进度条 keyup 不再重复提交已经由快捷键处理的左右跳播，避免旧值覆盖新目标或过早撤下画面保持层。
- Tab 进入滑块时仍保留原生方向键调整；Home/End/PageUp/PageDown 保持滑块行为。
- 文本输入、输入法组合输入、弹窗、菜单、设置面板及 Ctrl/Alt/Meta 组合仍受保护。键盘操作不会主动唤出隐藏控制栏。

新回归覆盖普通、纯净、全屏模式：实际鼠标点击进度条后立即 M/R，随后方向键、J/L、C、Space/K 和全屏/纯净退出；还验证 Tab 重新启用原生滑块操作。

其中一轮初始测试遇到上一播放器最后的进度请求晚于测试数据库重置，导致测试视频出现续播提示而未自动播放。测试明确选择“从头开始”获得确定起点，产品仍保留正常续播提示。

## 标签切换

旧逻辑每次查询都等待 200 ms，再用整块“正在加载视频…”替换封面墙；剧集归类也有固定延迟，没有分类页缓存。

当前：

- 分类、目录、排序、分页立即请求；仅文本搜索保留防抖。
- 共享 24 个分页结果的 LRU 缓存，20 秒内重复访问无需再请求；超过新鲜期保留同一查询的结果并后台更新，超过 120 秒丢弃。
- 缓存键包含分类、搜索、目录、页码、页容量、格式、观看状态、时长、排序等实际 API 查询条件。视图布局切换不重复查询。
- 快速查询不闪烁加载文字；真实慢请求仍显示反馈。不同查询不会用旧分类结果冒充当前数据；旧请求取消后不能写回当前页。
- 收藏、编辑、观看进度变化、扫描及媒体目录变更使旧版本缓存失效；剧集改名和封面版本更新也会清理相关缓存。
- 缓存覆盖平铺视频和剧集归类；剧集组件切换标签后重新挂载仍可复用。
- 进入播放器后暂停隐藏媒体库的列表请求，不因周期性保存进度增加后台列表查询。返回时重新核对进度和分类。
- 无数据的短暂加载保留高度，慢请求和错误仍可见，后台更新失败保留同查询的卡片并提供重试。

实测 UI 回归：先访问全部视频、电影、剧集，然后重复三轮切换，总共只有最初 3 次列表请求，重复切换的加载占位节点新增次数为 0。
